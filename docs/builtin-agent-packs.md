# 内置职能包 · 第一批

本批为 webuddy 原创入门模板，未引入第三方 Skill 或凭据。支持现有连续执行、版本快照和维护对话。没有选择固定强模型，也不会自动开启周期任务。不是独立可执行的智能体引擎，需由 webuddy 或兼容的 coding agent 执行。

| 职能包 | 用途 | 重点验收 |
| --- | --- | --- |
| 老项目渐进改造 | 维护已有系统、分步技术改造 | 行为兼容、最小改动、回归与回退 |
| 项目代码梳理 | 理解陌生项目、交接代码 | 真实文件与符号证据、事实与推断分开 |
| 自动化 CLI 构建 | 文件处理、批处理和命令行工具 | 隔离安装、参数/退出码、坏输入与覆盖规则 |
| 能力自进化设计 | 从失败与反馈改进 Skill 和方法 | 失败集与独立对照集、保留验收、版本回退 |

共用模块：接续工作与上下文整理、代码结构与证据定位、渐进改造与兼容验证、CLI 输入输出与可安装交付、从失败样例改进能力、成果/验证/限制说明。

## 使用

平台启动时自动安装 4 个内置职能体及 6 个共用模块，不覆盖已存在的职能体、团队维护版本或模块版本。职能体已含完整工作指导和验收标准，可关联项目直接开始；每个目录项提供原始职能包 ZIP 下载。

下载接口：登录后 `GET /api/v4/builtin-packs/{slug}/download`。slug 为 `legacy-modernization`、`codebase-map`、`automation-cli`、`evidence-evolution`。下载始终是平台原始模板，不是该职能体当前维护版本的导出。

已有职能体可通过维护模式上传单个 ZIP，要求读取 SKILL.md 并整理维护草稿，再沿用当前应用流程。上传 Skill 不自动创建职能体，不自动执行包内代码。项目代码 ZIP 仍走项目导入，不能把这两种上传混淆。

ZIP 包含 SKILL.md、agent.json 配置、modules/ 版本来源、evaluations.json 和 fixtures/ 样例。模块内容由单一源文件构建进配置；当前是构建时快照，尚非运行时动态模块引用。模块在库中可独立搭配到其他项目，使用内置职能体时通常不必再次选择相同模块。

## 构建与分发

源码位于 `factory/control/builtin_packs/`。在仓库根目录运行：

```sh
PYTHONPATH=. .venv/bin/python scripts/export_agent_packs.py
```

生成 `output/agent-packs/`：四个独立职能包、shared-modules.zip、SHA256SUMS 和 webuddy-starter-packs.zip 总合集。总合集应先解压再选单包上传。同一份源码重复构建得到相同字节。发行包不含密钥、第三方依赖或自动安装脚本。

## 验证边界

已验证压缩包可通过现有 Skill 路径与大小校验、样例引用存在、完整模块指导进入职能体配置、真实上传和下载一致、重复安装幂等，以及团队新版本不会被重新安装覆盖。每个包有至少两个验收场景和失败探针。

这些测试证明包格式与平台接入可用，不证明真实业务成功率。`validation_status=template-unbenchmarked` 明确保留；使用团队实际项目跑完正常、异常和独立对照样例后，再决定扩大使用。“自进化”不自动降低验收要求、修改平台权限或发布生产版本。
