# 垂直智能体工作室：设计包

设计日期：2026-09-09。设计阶段：Astra。后续实现：Luna，按任务包推进。本文档描述目标设计，不表示能力已上线。

## 要解决的问题

用户提供经验、Skill、Prompt 和样本，希望形成可以反复委派、针对具体业务、可维护升级的专业智能体。每次委派仍然经过需求、规划、执行、验证、交付与经验沉淀；用户直接取得成果，并能回答“哪个版本、哪套模型、依据什么标准做出来的”。

建议新增一级入口 **智能体**，内部包含「我的智能体」「Skill 素材」「评测与版本」。以现有工厂作为统一执行底座，新增可版本化的专业配置。首个样板是 **旧项目维护与工业格式转换**。

一个智能体的完整定义是：

> 职责与输入输出契约 + Skill 版本集合 + 职能分工与模型策略 + 流程模板 + 工具/环境约束 + 验证契约 + 交付契约。

同一个 Skill 可以被多个智能体引用；同一个智能体可以服务多个项目；每次运行固定一个具体配置快照。用户添加 Prompt 或 Skill 时产生候选版本，通过试跑与比较后再启用，不改写历史。

## 首版范围

首版完整支持：导入 Skill 包 → 检查并保留来源 → 配置专业智能体与不同职能的模型 → 绑定项目 → 在隔离环境试跑 → 独立验证 → 查看/下载成果 → 提出改进候选 → 评测并启用新版本。

先实现固定业务流程与可选任务分支。职能是持久工作单元的职责，不强制每个职责常驻一个进程，也不强制每个任务调用所有模型。Windows 专用工具、硬件锁、商业参考软件属于后续执行环境集成，首版明确显示缺少环境，不能用“配置成功”冒充可执行。

## 主要设计决定

- 专业职能和模型档位是两个维度；例如“格式分析”可以升级模型，但升级后仍然承担格式分析职责。
- 智能体版本、项目部署配置、模型注册配置分离；运行冻结三者解析后的完整内容与来源。
- 通用方法存入 Skill；项目事实存入项目知识；样本和真值存入数据集；验收例外存入受控残差登记。
- 模型能建议分工和改进，运行器决定权限、预算、版本、调度和验收。
- 同一任务的验证器不能修改生产文件、参考数据或残差规则，也不能批准自己提出的例外。
- 保留原有运行、成本与交付基础设施，逐步扩展，避免出现两个互不相通的工厂。

## 使用本设计包

Luna 开始前读取所有四份文档并核对当前仓库差异。前一轮成果预览/下载改动尚在工作区，必须保留，不能当作需要清理的临时内容。先做实现计划中的 M0–M1，再逐阶段交付；每阶段必须能从真实界面/接口验证。
