## 登记操作

项目页点击“登记项目”，选择已发现的工程，确认显示名称即可。服务器自动识别目录、仓库标识、当前本地分支；没有 GitHub remote 时自动生成稳定的本地标识，不要求用户编造 owner/name。重复登记、候选变化及不安全路径会被拒绝。候选接口不会返回路径或 remote 中的凭据。

当前发现范围为配置的工程根目录下，前 200 个直接子目录中的已有 Git 仓库，需有有效提交和当前本地分支；不跟随目录符号链接。根目录由部署配置维护，用户表单不填写。此功能连接已有工程，尚未增加上传工程或远程克隆入口。

## 旧版本问题的处理

- 旧页面轮询收到 401 后停止自动请求，手动恢复才继续；兼容 Axios 错误结构，旧请求不能停止已恢复的新会话。已经加载的旧构建需要关闭或刷新，本地修改不能直接停止远端旧标签。
- 服务实际读取 FACTORY_STATIC_DIR；HTML 与缺失资源响应禁止缓存。Caddy 模板统一反代控制服务，basic auth 不替代应用登录。
- 旧 runtime 路径和缺字段的 probe 请求提供明确刷新提示，不放宽接口验证。
- 项目保存 409 后保留编辑内容、读取并展示最新配置，用户明确审阅后才使用最新版本再次提交；编辑中的内容不会被后台刷新覆盖。
- 发布失败保留可下载成果，并记录运行编号、错误类别及可用的上游 HTTP 状态；不记录原始凭据或请求 URL。此次未获得线上原始异常，不能归因已有 502。
- 工程根目录示例修正为 /home/ubuntu/projects；不覆盖任何线上环境文件。
- 部署文档说明独立构建、同一静态来源及发布切换。未清空 /srv/factoryweb、修改线上 Caddy 或关闭远端浏览器。
- 外部扫描器的拒绝响应保持原行为。
