# Luna 实现计划 v2：优先交付两条对话闭环

2026-09-09。本计划取代第一版 M0–M6 的首版范围。设计由 Astra 完成，后续实现使用用户指定的 Luna；本次修订不代表已开始实现或部署。

## 实施约束

以当前 SYSTEM-DESIGN.md 为主，MAINTENANCE-AGENT.md 提供领域约束。保留前一轮成果归档/预览及发布错误修复；不要删除工作区改动、运行数据或恢复文件。检查 AGENTS.md、真实代码和测试基线后再动手。

复用已有 Service、队列、Provider、项目、费用、验证和 deliverables。首先画清已有 SDK 工具循环与应用持久循环边界，扩展现有执行路径。没有证据表明必须新增时，不建立第二个 loop、调度器或微服务。

## A：从职能体开始做事

完成最小 Agent/AgentVersion 严格 schema、持久化和兼容迁移；版本保存完整配置，旧 Run 不带 agent_id 仍正常。首页提供职能体入口、通用助手、开始任务和维护动作。

做事对话支持提交需求、附件、选择或关联项目，调用真实现有运行链路。项目不作为聊天前的必填表；执行需要工作区时才落项目。运行绑定冻结版本。对话内显示进展和成果卡，可预览和下载。

验收：从维护员卡片提交一个明确任务，实际完成检查并下载成果；重进页面仍保留对话与 Run；旧项目入口正常。此阶段使用受控初始配置，清楚标注维护功能尚未完成，不伪装为首版全部完成。

## B：通过对话教会它

实现 mode=maintain 会话和最小受控工具：读取原包/资源、读取现行配置、提交结构化草稿补丁、查看差异与检查结果。模型调用走现有 Provider 和账本；草稿补丁带 expected_revision，由程序校验和事务保存。

实现流式 ZIP 上传、原包与清单保存、Windows 路径规范化及越界/重复/大小检查。上传仅解析，不安装或执行脚本。模型结合 Skill 和口语要求生成草稿，自动保存，在聊天展示变更卡及冲突。

应用入口校验权限、修订号、幂等键与基准版本，生成不可变版本并切换默认。支持继续调整、仅项目应用、撤回和恢复上一版。针对关键歧义追问；不把每句补充都变成审批，不把模型建议当已获授权。

验收：上传用户附件、补充“以客户当前版本为准”，看到来源、冲突处理和更新内容；刷新/重启不丢草稿；应用后新任务采用新规则，活动 Run 仍用旧规则；回滚可验证。使用 fake Provider 验证持久化与错误路径，再用已配置真实模型验证整理链路，不能混称。

## C：模型、恢复与实际可用性

职能体可选默认模型，按需覆盖分析、执行、独立验证和维护对话模型。自然语言设置产生可验证配置；适配器核验参数，显示实际值和来源。保持现有隔离限制、统一预算与费用，明确失败原因与受控 fallback。

验证工具回执持久化、断线恢复、取消、重复提交、预算耗尽、同类失败停止、上下文压缩后约束恢复。代码工作保留独立验证上下文，任务验收证据和真实产物一致。维护模式不具备项目发布工具。

用旧项目维护样板完成真实端到端演示，具备环境时才构建实际安装包。没有环境显示缺什么，已可交付的源码/报告仍能下载。

## 文件落点建议

不是强制新建所有模块：先查已有存储、对话和路由可否扩展。新增 Agent schema/store、维护草稿与应用逻辑、Skill 资源解析、上下文构建各保持清晰职责；前端复用聊天、Run 和成果组件。新增 HTTP 接口遵循仓库现有版本约定，不为设计整齐强制整站升级 v4。

最小接口语义：列出/创建职能体、读取详情与版本；创建两种模式会话、提交消息及读取事件；上传并读取有权限的素材；读取草稿/差异、应用草稿和回滚。聊天生成只能提交草稿；应用由已授权用户动作触发的服务操作完成。所有写操作有鉴权、参数校验及适用的幂等/并发控制。

## 完成检查

1. 从职能体入口发起项目工作，拿到真实可用成果。
2. 维护对话接收 Skill + 口语要求，整理、保存、应用、回滚全链路真实可用。
3. 新旧运行版本隔离，项目事实不污染通用规则。
4. 两个职能体采用不同模型配置；阶段覆盖实际被调用，未知配置有明确错误。
5. ZIP 安全边界、并发409、应用重试、恢复、取消和预算停止通过针对性测试。
6. 浏览器检查真实界面：无需先填一串后台表单，进展与成果直接可见。
7. 记录代码、验证、限制及部署步骤；生产部署另依实际授权和目标环境执行。

A–C 完成才称首版闭环完成。无需先实现历史方案的独立评测、通用 DAG、多 Agent 管理和复杂注册表。领域关键回归检查必须有，不能借精简取消验证。
