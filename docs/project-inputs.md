# 从资料开始项目

项目的新建入口支持空白工作区、上传文件 / ZIP、连接已有工程。职能体“开始任务”也提供“上传资料并建立项目”，自动使用当前职能体，成功后选中项目并返回任务输入；上传不自动提交模型任务，不影响职能体的人工签署流程。

- 单个 ZIP：沿用项目导入，安全解包到工作区根目录并建立 Git 基线。
- 其他文件或多个文件：逐字节保存到工作区根目录；可以是文档、图片、格式转换样本或未知扩展名的二进制文件。多个文件中的 ZIP 原样保留，不递归解包。
- 非文本格式是否能直接理解，取决于执行器的读取工具；需要解析器时由后续编码任务实现，上传成功不等于格式转换已经通过验证。

新资料 API 为 `POST /api/v2/projects/import-files`，使用 multipart `files`、`name`、`idempotency_key` 和可选 `agent_id`。沿用 admin-only、来源校验、CSRF、流式请求体限额、幂等与项目职能体绑定。最多 100 个文件、总量约 20 MiB（预留 64 KiB 归档开销）；不接受目录路径、冲突文件名、凭证名和保留文件。上传不运行脚本、不安装依赖；原始字节和导入报告可追溯，Git 工作副本可直接供执行器读取。

默认项目不设美元停止线，只统计费用和 token。成员月度 token 限额在团队页管理，跨该成员的项目累计；旧的显式项目限额仍保留，配置为仅监测即可不按项目拦截。此次没有把历史项目限额静默删除，也未改变团队权限语义。

## 适配的临时故障

skill 包的每个适配及验收分片在可重试的上游错误（429、502/503/504、网络和超时）后等待 5 秒、15 秒，最多追加两次调用。每次调用单独计量并重新检查预算，已完成分片复用；等待期间可以取消。预算不足、授权或配置错误、不合法映射和主动取消不会自动重试。超过重试次数后显示暂停原因，保留原包及分片供继续。不会无限重试、自动签署或执行来源脚本。
