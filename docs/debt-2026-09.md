# 2026-09 工程债务清理

本轮仅拆分职责、移除退役 HTTP 层与相应死代码，不合并两套引擎，不新增产品功能。旧 CLI 引擎冻结维护，只修缺陷、不加功能。

## 退役边界

- 新控制面的认证与 CSRF 边界保留。旧控制室 HTTP 路由与 SSE 转发、旧 HTTP 实现及对应命令入口已删除；已认证的未知 API 路径统一返回 404 与迁移提示。当前工作台继续使用既有版本化 API。
- 旧 CLI 的 run、loop、queue、审计与 backlog，以及 dispatcher、gates、supervisors 均保持原实现。
- 实时快照、快照差、现场文件猜测和 live 流只服务退役 HTTP 层，连同专属测试删除。
- replay_stream 仍被 CLI 使用，因此保留；其事件形状、时间戳、倍速、snapshot/replay.end 包装和 JSONL 落盘均不变。使用：`factory replay T-142 --db audit.db --speed 0 > rec.jsonl`。
- 删除的权限审计接口测试只覆盖退役 HTTP 投影；底层审计与权限门测试保留。前端格式化测试里的历史示例路径只是普通文本，不是 Python 模块依赖。

## Service 职责

`factory/control/service.py` 从 1849 行降为 552 行，继续作为门面保留全部公开方法签名、调度、初始化、maintenance 作业及政策协调。

| 模块 | 职责 |
| --- | --- |
| verification.py | 验收合同、隔离快照、版本化模板加载、覆盖检查与 coverage_retry |
| run_billing.py | 用量对账、预算计算、停机证据、未完成调用费用与验收预算预留 |
| run_lifecycle.py | 澄清、继续、审批、重试、取消、丢弃、失败终态、发布与交付记录 |
| recovery.py | 重启恢复、checkpoint 接续及安全的连续执行阶段选择 |
| run_execution.py | 原规划与执行方法、修复循环、运行事件投影 |

规划与执行也必须移出门面才能满足 600 行限制；这里只搬迁原函数体，没有替换执行设计。跨职责调用仍通过 Service 门面，保持可替换的测试/执行器接入点。局部 imports 已归并到所属模块顶部；当前拆分没有引入循环依赖，不需要保留局部 imports。原内部辅助函数在门面保留兼容导入。

## 核对方式

- 对搬迁前后的全部 Service 方法比对参数、默认值、docstring 与去除 imports 后的 AST；函数体和辅助函数一致，包括 SQL/提示文本的原始字符串内容。
- 原有 Service 测试断言不变；仅两处模拟执行时钟的 import 路径迁到 run_execution。
- 保留并运行旧 CLI 回放、调度、预算、验收及恢复测试；补充退役 API 的 404 与命令移除测试。
- 后端完整回归排除已有 smoke marker 标注的真实 Claude CLI 登录用例；前端构建与 Vitest 保留。
- uv.lock 不变。README、运行手册、接口契约及旧 SSE 反代示例同步清理。

app.py 自身拆分、两套引擎合并与任何新功能留待后续。

## 2026-09-15：app.py 路由拆分与测试隔离

仅把认证、运行操作与 GitHub webhook 分别迁到 `auth_routes.py`、`run_routes.py`、`webhook_routes.py`；密码修改处理函数从原 team router 移入认证 router，Password 请求模型保持原定义。app.py 保留应用组装、异常处理、原位认证/CSRF/admin 边界、原有项目注册/配置处理及静态服务。既有 project_routes、runtime_routes、spec_routes、remote_routes 未改。兼容导出原 app 模型名称。没有双栈合并或新权限语义。

拆分前从原 app.py 与 team_routes.py 提取路由参数、装饰器（含状态码）与异步属性，存为 `tests/fixtures/app-route-contract.json`，测试逐项比对搬迁后的同一清单。中间件保留原位，另用原文 SHA-256 校验逐字不变。既有路由测试断言不改。规格引用编译是本轮单列功能，独立覆盖其源字段和指纹变化。

巡检测试的隔离问题：停止标志不是线程退出屏障，已越过停止检查的调度迭代仍会扫描持久队列；手动 tick 后可能与该线程竞争领取同一巡检。用事件屏障可以确定性复现此窗口。测试现在先停止并 join 调度线程，再配置、以 `next_at + 1.0` 显式时间触发巡检。app_env 为默认函数作用域，每次新建 tmp_path 下的仓库、Service 和数据库，没有跨用例共享项目或工作区。三次连续全量复跑结果写入本轮提交说明。

全量复跑另发现远程超时测试把两次 Python 冷启动算进 400ms 预算，偶尔尚未创建子进程就超时。该用例改用轻量 shell 假 SSH，仍启动真实子进程，保留原有超时、状态及子进程终止断言；远程执行产品代码不变。

部署更新以 [v3 RUNBOOK](v3/RUNBOOK.md#服务器更新顺序) 为准：自 `bc1c1ef` 的 `react-markdown` 依赖加入后，保持 `uv sync --frozen --all-extras` → `npm ci && npm run build` → 重启，不能复用旧前端依赖直接构建。
