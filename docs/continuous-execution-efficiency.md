# 连续执行的终端与收尾

Claude SDK 的一次执行使用一个持久隔离终端。每条命令仍经过原有命令规则和资源排队，宿主凭据不可见，共享 Git 元数据只读。后台预览服务、临时文件和依赖缓存可跨工具调用保留；每条命令的 shell 工作目录及导出变量不会继承，应使用明确路径。

终端生命周期是一次 SDK 执行，不跨进程重启或失败重试。执行完成、异常退出或被取消后，隔离进程及其子进程清理。恢复执行时重新启动服务；项目目录中的代码和验收证据保留。超时只终止该命令进程组，已有服务仍可使用。

执行指令要求完成真实需求和相关验收后交付。检查通过后，只因新改动、失败或未解决的需求重复检查。真实内容的裁切等缺陷应修复；不主动构造无限扩大的压力测试、未来扩展重构或额外功能。可选完善列入结果说明，不阻塞本次交付。独立验收保持不变。

`provider.timing` 记录首个 SDK 事件、首条助手消息、工具结果到下一条助手消息的间隔、较长的 SDK 事件间隔、观察到的上下文压缩及执行汇总。`command.completed` 分开记录资源排队 `wait_s` 与命令执行 `execution_s`。

这些是 SDK 边界的观测，不是上游 HTTP 请求计时：首条助手消息可能等整条内容生成后才出现，SDK 事件空档可能包含工具执行、生成、压缩、网络和内部重试。`http_ttft_s` 与 `upstream_queue_s` 保持空值，不能据此判断中转站速度。需要上游请求日志才能进一步拆分。

验证包含真实 Linux bubblewrap：跨调用访问后台 HTTP 服务、跨调用临时文件、不同会话临时目录隔离、超时后继续使用终端、关闭后的服务与临时文件清理。
