# 工作台实机检查与恢复入口修补

本轮使用 Computer Use 检查线上工作总览、项目列表、丑团项目与设置、运行详情、用量、团队额度、运行配置、能力中心两页，以及职能体维护、岗位清单和上传入口。点击保存复现设置错误，点击适配运行复现空白页。未为测试执行删除、签署或修改授权。

## 发现与修复

- 丑团项目没有保存需求分析预算，代码却使用隐藏的 5 美元默认值。缺省现在表示监测；明确设置的分析上限仍有效。项目切换仅监测时同步清空分析上限，团队额度和超时限制不变。
- 无实际修改的项目保存仍可能被运行状态拦住，前端又将任何 409 当作版本冲突。无变化保存不写审计、不涨 revision；真实并发修改仍检查 revision。只有版本确实变化才显示合并提示。
- 已经重试的旧预算暂停仍在待处理栏中。保留旧证据，显示后续运行入口，避免重复续跑；重试保留原工作流来源，通用任务不会绕过需求分析。
- 外部包适配遇到上游 504 后仍显示“处理中”。现在读取实际运行状态，显示失败原因、已完成映射和验收分片，并可用既有 continue 接口恢复。旧记录尚无总片数时显示待统计。
- 适配计划缺少 depends_on 导致图组件白屏。新计划补全字段，前端兼容历史计划。
- 职能体页分别显示已上传资料、适配草稿、岗位清单的已装备能力。上传并不等于启用；独立验收和人工签署仍不可跳过。
- 统一若干表单的下拉、复选框与栅格样式；遗留模块通过来源或摘要消歧。

## 实际业务状态的边界

检查时，丑团旧预算暂停已有后续运行达到 ready_for_review；这不代表历史运行已补做新的保真验收。逆向工程岗位清单为零项，外部资料保存成功但适配上游 504，尚未成为可用 skill。其实际业务是格式转换；本次不自动更改人签身份、不添加进攻授权、不替用户签署。

浏览器标签连接在后续复测中多次超时；原生窗口控制已用于上述实际复现，但不能将组件测试当作所有页面均实机通过。部署后的实际复测结果另行记录。

## 回归范围

后端覆盖缺省分析预算、无变化保存、预算放宽、重试来源与待处理去重、适配实际状态与分片进度；前端覆盖保存冲突、监测表单、运行筛选、遗留模块标签、暂停续跑、资料清单及历史适配计划。

全量回归发现既有会话连续性测试仅给子进程 0.2 秒启动，繁忙环境中先超时再产生会话事件，导致旧会话 ID 断言失败。测试改给 3 秒余量，工作进程仍阻塞 10 秒，原有超时、会话保留和重复事件断言不变。文件级 21 项通过，随后重跑全量。
