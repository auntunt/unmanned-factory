# 持续托管编码

新建、采用自主策略的网页和职能体编码任务，默认使用 `continuous` 执行模式。平台组装需求、工程上下文和授权信息后直接启动编码，不再先调用模型生成固定模块 DAG。六环保留，作为需求、执行、验收和交付的展示。

## 执行与恢复

一个任务使用一个独立工作区、一个模型配置和持续会话。Claude 在其中自行规划、修改源文件和正常项目配置、安装依赖、运行应用与测试。可信检查由平台在编码结束后执行一次；失败时把结果交回同一工作区和会话修复，最多两次。不会因为涉及多个文件就拆成多个模型任务。

明确的上游临时错误（如 429、502、503、504）最多自动恢复两次，保留目录、依赖和已观测到的会话 ID。模型错误、权限错误和取消不会被当成可无限重试的连接故障。重复 session ID 只表示会话身份，不再作为新的进展事件。没有用武断的“几分钟没输出”阈值中断健康的长命令或生成。

平台保留工作区隔离和 Git 元数据边界。正常测试和配置文件修改进入最终验收证据，不再仅根据这些文件名停止任务。终端命令结果穿过 SDK 子进程后仍保持结构化，包含退出状态、耗时及有界输出。

最后进行独立验收。实际验收不通过时，返回当前编码会话修复一次再验收；验收连接临时失败则恢复验收，不让编码模型重新实现。执行、检查、验收和修复共享本轮总时限。独立模型审查不是业务正确性的数学证明；交付需要实际运行证据。

启用重启恢复的任务从持久检查点接续同一目录和会话，重新核对项目权限、Git 归属、检查配置和模型配置。发布中的任务不自动重放外部发布。

## 兼容与迁移

旧任务保持原 DAG 执行语义，不在运行中自动重解释原计划。管理员可以在停止旧执行后调用 `continuous_migration.migrate_to_continuous`，将已完成提交和未完成草稿合并到新的单一工作区，再显式采用。原目录和分支保持不变；冲突会停止迁移并保留两边，不能把冲突工作区作为迁移成功采用。

迁移保留原计划的完整任务说明和验收条件。原先的多个模型会话无法合并成一个会话，因此首次迁移从新会话读取现有成果；之后持续使用这一会话。新任务与旧任务的事件、费用和交付历史仍可追溯。

现有“执行中补充需求”仍在成功边界采用反馈；本次没有宣称支持随时中断生成并实时注入口语消息，也没有修改用户的模型 Key、计费或插件配置。
