# 外部 skill 包摄取与适应化

职能体详情使用统一的“为职能体添加能力”入口，支持 Prompt、ZIP 与已挂载目录，无需先绑定项目。职能体列表的“导入职能体”仅恢复 webuddy v1/v2 原生整包。外部包只作不可信资料，不执行其脚本。

## 运行与评审

摄取创建普通运行记录，通过现有持久队列、四任务并发上限、费用与团队额度闸门调度。使用平台配置的 standard 做适配、planner 做独立验收；两次均由原有 SDK runner 调用，不启动另一套模型执行服务。有限费用保留独立验收份额。

该工作流的产物是数据映射，不是代码提交，因此独立验收核对的是冻结包的 SHA256 和逐项映射证据，使用现有 acceptance_ledger。不会运行包中自带的测试、门禁或安装程序。验收不完整或失败仍为待处理运行，不生成正式职能体。可继续原运行，不允许用普通重试丢失摄取来源。

验收通过后进入人签评审：结构与 SOP、断言、宿主映射、工具/MCP 前置条件、安全分类和注入风险均可查看。核对方法和映射依据可修改；身份和授权标记由人签确认。修改映射后先保存再签署，修订号冲突返回 409。原始来源与适配模型的报告保留在审计记录中。签署事务将 skill 与新清单 revision 加入目标职能体，并解除运行的待处理状态；兼容旧的项目范围摄取时仍可创建新职能体。草稿不会提前成为可执行能力。

## 格式与来源

每个目录下的 `SKILL.md` 或带 `name` frontmatter 的 Markdown 文件视为一个 skill，支持目录树与扁平集合；识别其 frontmatter 的 name/description，UTF-8 正文保留原始换行，不做 strip。记录 ZIP 原字节的 SHA256，过滤垃圾后的包存档；目录会先生成冻结 ZIP，再按相同流程处理。

清单沿用 `webuddy.agent-pack/v2`，增加 `manifest.adaptation` 保存 SOP 步骤（含固定 skill 引用）、映射决议、依赖、风险和人签信息。每个 skill 的 `external_source` 保存原包 SHA256、来源路径、原始文件 SHA256、正文 SHA256、摄取 id。现有 v1/v2 读取继续支持；导出、重新导入会保留溯源和授权标记，并重映射实例内 skill id。

原文 MUST/MUST NOT 和 gate 句必须逐项落到对应步骤，附原文依据和核对方法。不能机械核对的断言明确标为 advisory；只有 mechanical 断言并入正式清单的逐项验收 criteria。语义抽取仍需独立模型与人共同核对，机械检查只证明可核对的结构、引用、原文覆盖及哈希事实，不保证自然语言分类绝无遗漏。

大包按资料分片适配和独立验收，不静默截断；岗位一次装载仍最多 24 项且保持原提示词长度上限。非 UTF-8 附件保留文件哈希并标记不可解析，不执行它们。

## 安全映射

摄取调用使用全新的空临时目录，不继承会话、项目挂载、用户设置或 MCP。Claude 工具列表为空，权限回调及 PreToolUse 对所有工具一律拒绝。外部材料只进入不可信数据段，不进入固定系统指令。当前 Codex 与 DSH 适配器没有经过验证的零工具模式，因此摄取会明确拒绝这些配置，不退化到普通 coding 权限。可以使用现有运行设置调整 standard/planner，无需新凭据系统。

平台保守识别授权门与进攻性 ACT，模型可追加 `authorization_required`，不能清除平台标记；身份也是建议，只有人签的身份会生效。读者祈使语句登记为风险，原始正文仍为资料保存，而不是可执行路由或系统指令。

签署时逐项确认 `requires_authorization`。此标记在模块编辑、清单冻结、职能包往返中保留。每次模型派发前核对本次 run、冻结 skill 版本与逐目标人工授权；没有授权则拒绝执行进攻性 skill。管理员在暂停运行的目标授权卡逐项列出目标，授权入审计，仅对当前运行有效，不自动转移到重试创建的新运行。未完成规划时授权后重新入队；已有计划沿现有继续流程恢复。

这不是新建远程攻击工具或网络防火墙。目标清单是平台显式授权记录及运行范围约束，底层工具仍沿用现有沙箱与权限模型。无授权时不派发含进攻性 skill 的运行；可另用不含进攻能力的职能体提交只读、离线分析。

## unsupported 与依赖

`master-route`、`case-init`、`tool-index`、`bootstrap-manifest`、工作目录、scope、gate 只能分别映射为平台已有 SOP、运行队列、MCP registry、清单、工作区、范围声明、验收账本。逐条保留来源与依据。所有 `.sh/.ps1/.bat/.cmd` 文件入口均为 unsupported：**该能力在本平台不可用**。逻辑映射不代表执行原脚本。

工具与 MCP 声明仅整理成带来源的运行前置条件；实际连接继续使用现有数据源/MCP 配置。本轮不会自动下载、安装或注册任何依赖，不会执行外部路由契约，也不会无人签启用职能包。签署后的职能体继续使用原有清单版本、回滚和证据驱动进化机制。


## ZIP 文件数与上传入口

统一“添加能力”入口由平台判断通道。单附件上限 500 文件，多 skill 或超过 500 文件走适配；外部摄取及原生整包导入上限 3000 文件，空目录不计数。旧单附件 API 保留原限额与具体错误提示。

任意层级的 `__MACOSX/`、`.DS_Store`、`._*`、`.git/`、`.svn/`、`.hg/` 与 `node_modules/` 成员在计数、单文件大小校验与内容读取前过滤，既不进入文件清单，也不保存在数据库 ZIP 中。摄取仍记录用户原始上传包的 SHA256，每个保留文件的正文及哈希不变；数据库保存过滤后的包，后续评审继续引用原包来源哈希。

原有体积限制不变：ZIP 20 MiB、单文件 2 MiB、展开总量 100 MiB、压缩比 100:1；路径、重复文件、符号链接检查不放宽。目录读取仍限制在管理员明确挂载的根目录内。错误显示后端具体限额，不仅显示 HTTP 状态码。

版本控制历史与依赖目录使用相同过滤规则，ZIP 和挂载目录入口均生效。过滤成员不解压、不进入适配文本或数据库；原始 ZIP 的 20 MiB 上传限制仍在过滤前生效，保留文件的大小、展开总量和压缩比限制不变。

## 岗位级装备与入口（2026-09-16）

职能体列表只管理“新建 / 导入职能体”。原生 v1/v2 ZIP 会创建完整职能体；
第三方资料请进入已有职能体的 **为职能体添加能力**：

- 粘贴 Prompt：进入既有维护会话，整理成草稿后人工应用。
- ZIP：服务器检测过滤后的文件数与 SKILL.md 数量。单 skill 且不超过 500 文件时保存为该职能体维护附件；多个 SKILL.md 或超过 500 文件时进入适配与人签（最多 3000 文件）。界面回显检测数量和实际通道。
- 目录：管理员设置 `FACTORY_SKILL_IMPORT_DIR` 为独立只读资料挂载根目录，输入根目录内的相对路径。未设置时提示上传 ZIP；不允许任意绝对路径、上级目录、符号链接或特殊文件。目录入口走适配与人签。

`POST /api/v4/skill-ingestions` 与 `/directory` 的 `project_id` 可省略；省略时必须有 `agent_id`。
适配运行 `project_id=null`，不创建隐藏项目、不进入任何业务工作区。每次适配与独立验收调用使用空的临时 scratch；退出、取消或异常均由上下文管理器清理。
运行仍使用原持久队列、并发上限及费用记录。目录读取与包解码由平台完成；模型禁用全部工具，不提取或执行任何外部脚本，也不读取业务项目指令。

`POST /api/v4/agents/{aid}/abilities` 自动分流 ZIP，返回 `channel`、`skill_count`、`file_count`、可读 `message` 与附件或适配运行。错误保留后端具体原因。
`GET /api/v4/skill-ingestions?agent_id=...` 返回该岗位的适配草稿。无项目模式的摄取、评审与签署仅管理员可操作。

人签前不会更改岗位清单。签署时将原包保存为该职能体的不可变 `skill_assets`，全部来源 skill 生成有岗位归属的版本化模块。人签在一个事务内追加 manifest revision，保留当前 identity、已有引用、原断言以及历次映射依据；身份变化时要求刷新评审，不以适配建议覆盖人签身份。
岗位专属模块不会自动进入其他项目或职能体的模块建议库；通过该岗位的 manifest 冻结后才用于实际任务，跨岗位复用仍需显式导出与导入。

### 大包的适配与装载边界

适配不再用“24 个 skill / 10 万字符”拒绝整个资料库。平台分片读取全部资料，保留每个文件的原始哈希、完整文本和分片位置；适配仍是同一次受控运行，每片独立核对，任一片 fail/unverified 即不允许签署。已完成映射和分片验收证据持久保存，调用失败后续跑复用已完成分片。
非法 frontmatter 不猜字段，原文归档并列为人审风险。

“保存能力库”与“同时装载”不同：岗位清单仍最多引用 24 项，编译提示词仍有原来的 10 万字符上限。大包人签时明确选择本次加入岗位清单的能力；其他能力作为已签署随附能力保留，可在清单中按需加入。签署确认全部授权标记，未选择不等于删除或解除授权；完整风险、宿主映射、原包与 skill 哈希保存在适配记录及清单中。导出会携带随附能力及原始附件，导入重新分配岗位和模块 ID。

全部 ZIP 通道继续保持 20 MiB 压缩体积、单文件 2 MiB、100 MiB 解压总量和 100:1 压缩比闸门。`.git/`、`.svn/`、`.hg/`、`node_modules/`、`__MACOSX/`、`.DS_Store`、`._*` 在文件计数、单文件大小校验及持久化前过滤；原始上传包整体 20 MiB 上限仍生效。

不做：自动下载安装工具/MCP、执行外部包脚本、无人签启用、把 scratch 暴露为业务项目、自动跨岗位共享。

### 上传后的状态与恢复

维护页同时显示已上传附件、适配草稿和岗位清单的已装备能力数量。适配草稿读取实际运行状态：上游错误暂停时显示原因与保存的分片进度，可从原运行继续，不必重复上传。适配和独立验收完成后仍需人工核对并签署；只有清单引用的 skill 会挂载到后续任务。历史计划缺失依赖数组也可正常查看运行详情。
