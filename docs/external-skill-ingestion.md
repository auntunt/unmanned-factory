# 外部 skill 包摄取与适应化

入口位于职能体工作台可折叠的“导入”区块，选择“外部 skill 包·适配人签”标签。“职能包 v1/v2”标签用于恢复 webuddy 导出的原生职能包；误把外部 ZIP 传到此处会给出具体原因和正确入口，不会绕过适配与人签。管理员选择项目，上传 ZIP，或填写项目工作区内已挂载的相对目录。目录读取不接受链接、特殊文件或越界路径；ZIP 沿用现有大小、路径和链接校验。不会解压到编码工作区，不执行源包脚本。

## 运行与评审

摄取创建普通运行记录，通过现有持久队列、四任务并发上限、费用与团队额度闸门调度。使用平台配置的 standard 做适配、planner 做独立验收；两次均由原有 SDK runner 调用，不启动另一套模型执行服务。有限费用保留独立验收份额。

该工作流的产物是数据映射，不是代码提交，因此独立验收核对的是冻结包的 SHA256 和逐项映射证据，使用现有 acceptance_ledger。不会运行包中自带的测试、门禁或安装程序。验收不完整或失败仍为待处理运行，不生成正式职能体。可继续原运行，不允许用普通重试丢失摄取来源。

验收通过后进入人签评审：结构与 SOP、断言、宿主映射、工具/MCP 前置条件、安全分类和注入风险均可查看。核对方法和映射依据可修改；身份和授权标记由人签确认。修改映射后先保存再签署，修订号冲突返回 409。原始来源与适配模型的报告保留在审计记录中。签署事务同时创建 skill、清单 revision 和正式职能体，并解除运行的待处理状态；草稿不会提前出现在可用职能体列表中。

## 格式与来源

每个目录下的 `SKILL.md` 或带 `name` frontmatter 的 Markdown 文件视为一个 skill，支持目录树与扁平集合；识别其 frontmatter 的 name/description，UTF-8 正文保留原始换行，不做 strip。ZIP 原字节存档，以 SHA256 标识；目录会先生成冻结 ZIP，再按相同流程处理。

清单沿用 `webuddy.agent-pack/v2`，增加 `manifest.adaptation` 保存 SOP 步骤（含固定 skill 引用）、映射决议、依赖、风险和人签信息。每个 skill 的 `external_source` 保存原包 SHA256、来源路径、原始文件 SHA256、正文 SHA256、摄取 id。现有 v1/v2 读取继续支持；导出、重新导入会保留溯源和授权标记，并重映射实例内 skill id。

原文 MUST/MUST NOT 和 gate 句必须逐项落到对应步骤，附原文依据和核对方法。不能机械核对的断言明确标为 advisory；只有 mechanical 断言并入正式清单的逐项验收 criteria。语义抽取仍需独立模型与人共同核对，机械检查只证明可核对的结构、引用、原文覆盖及哈希事实，不保证自然语言分类绝无遗漏。

一个包最多 24 个 skill；全部文本最多 100000 字符。超过限制明确拒绝并建议按岗位拆包，不静默截断。非 UTF-8 附件保留文件哈希并标记不可解析，不执行它们。

## 安全映射

摄取调用使用全新的空临时目录，不继承会话、项目挂载、用户设置或 MCP。Claude 工具列表为空，权限回调及 PreToolUse 对所有工具一律拒绝。外部材料只进入不可信数据段，不进入固定系统指令。当前 Codex 与 DSH 适配器没有经过验证的零工具模式，因此摄取会明确拒绝这些配置，不退化到普通 coding 权限。可以使用现有运行设置调整 standard/planner，无需新凭据系统。

平台保守识别授权门与进攻性 ACT，模型可追加 `authorization_required`，不能清除平台标记；身份也是建议，只有人签的身份会生效。读者祈使语句登记为风险，原始正文仍为资料保存，而不是可执行路由或系统指令。

签署时逐项确认 `requires_authorization`。此标记在模块编辑、清单冻结、职能包往返中保留。每次模型派发前核对本次 run、冻结 skill 版本与逐目标人工授权；没有授权则拒绝执行进攻性 skill。管理员在暂停运行的目标授权卡逐项列出目标，授权入审计，仅对当前运行有效，不自动转移到重试创建的新运行。未完成规划时授权后重新入队；已有计划沿现有继续流程恢复。

这不是新建远程攻击工具或网络防火墙。目标清单是平台显式授权记录及运行范围约束，底层工具仍沿用现有沙箱与权限模型。无授权时不派发含进攻性 skill 的运行；可另用不含进攻能力的职能体提交只读、离线分析。

## unsupported 与依赖

`master-route`、`case-init`、`tool-index`、`bootstrap-manifest`、工作目录、scope、gate 只能分别映射为平台已有 SOP、运行队列、MCP registry、清单、工作区、范围声明、验收账本。逐条保留来源与依据。所有 `.sh/.ps1/.bat/.cmd` 文件入口均为 unsupported：**该能力在本平台不可用**。逻辑映射不代表执行原脚本。

工具与 MCP 声明仅整理成带来源的运行前置条件；实际连接继续使用现有数据源/MCP 配置。本轮不会自动下载、安装或注册任何依赖，不会执行外部路由契约，也不会无人签启用职能包。签署后的职能体继续使用原有清单版本、回滚和证据驱动进化机制。


## ZIP 文件数与上传入口

维护模式的「添加 Skill（ZIP）」用于单个 skill 附件，上限 500 个实际文件；含多个 SKILL.md 或超过该上限时，显示具体原因并提供职能体页「外部 skill 包·适配与人签」链接。链接直接展开导入区并选中外部包标签。外部 ZIP 摄取、已挂载目录摄取及职能包 v1/v2 导入使用 3000 文件上限；空目录不计文件数。

任意层级的 `__MACOSX/`、`.DS_Store` 与 `._*` 成员在计数与内容读取前过滤，既不进入文件清单，也不保存在数据库 ZIP 中。摄取仍记录用户原始上传包的 SHA256，每个保留文件的正文及哈希不变；数据库保存过滤后的包，后续评审继续引用原包来源哈希。

原有体积限制不变：ZIP 20 MiB、单文件 2 MiB、展开总量 100 MiB、压缩比 100:1；路径、重复文件、符号链接检查不放宽。已有目录读取边界及 24 个 skill / 100000 字符的适配输入限制也保持不变。错误显示后端具体限额，不仅显示 HTTP 状态码。
