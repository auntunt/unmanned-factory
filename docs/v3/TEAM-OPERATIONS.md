# 小组试用：成员、权限与额度

## 使用范围

本版面向一个互相信任、共享项目记录的小组。所有已登录成员均可阅读项目、运行、知识和导出；项目分配控制执行权限，不是不同客户之间的数据隔离。执行发生在工厂服务器，以服务器配置的 Provider 身份调用 SDK。可以使用该身份支持的订阅或 API 认证，本版不按成员切换个人 Codex/Claude 登录身份。

已有账号迁移为管理员，旧会话保留。通过命令行创建的账号仍是管理员；通过“团队与额度”创建的账号默认是成员。密码至少 12 字符。账号停用、角色变化、管理员重置密码或本人改密都会撤销已有会话。系统禁止停用或降级最后一名启用的管理员。

管理员创建成员后，分配项目、设置成员月额度，再交给成员使用。新成员没有执行项目，不能凭空发起调用。成员可操作自己在已分配项目中发起的运行；管理员可以配置运行环境、可信检查、项目策略、能力版本和发布。页面隐藏无权操作的入口，服务端再次验证权限，未知写接口默认仅管理员可用。

## 额度口径

- 按 UTC 自然月计量；统计从团队计量启用时开始，历史调用没有虚构回填。
- 同一调用同时计入成员、项目和工作区三个范围。Webhook 等系统任务计入项目与工作区，归属单列，不随意记到某位成员。
- tokens 为完整调用的总输入加总输出。Codex 输入已经包含缓存输入，不能重复累加；Claude 的缓存读取、缓存创建和未缓存输入合计后再入账。
- `null` 表示不限额，`0` 表示禁止下一次调用。额度数字是工厂内的统计，不等于供应商余额、credits 或美元费用；本工厂之外的调用无法在此限制。
- 每次规划、开发、重试、集成修复及运行探针之前，用数据库事务预留额度。多个任务并发也不能重复占用同一份可用余额。默认每次预留 20,000 tokens，可由管理员调整。
- 预留是 SDK 任务的调度门槛，不是单次任务的硬封顶。SDK 内可能包含多轮模型请求，实际用量可能超过预留；完整结果回来后据实结算并阻止超额后的下一次派发。严格账单封顶还需供应商自身限制。
- 中断、超时、缺失或格式异常的用量保留为“待核对”，不记为零。有额度上限的范围出现待核对用量时，停止新调用，直到管理员提供实际数量与核对依据。
- 重启将未完成预留保留为待核对；跨月也不消失。人工核对必须附原因，只能结算未知记录，重复核对被拒绝；权限、额度和核对操作留有审计。
- 已经运行中的调用不能靠停用账号立即撤回，停用与撤回权限会阻止下一次派发；需要立即停止时取消对应运行。

成员看板首先展示自己的额度；管理员看工作区总量和成员列表。成员、项目和工作区任一范围余额不足都会阻止继续。调低额度不回滚已经发生的使用，也不会释放仍未核对的占用。

## 让自动执行真正跑起来

1. 在独立 Git 仓库登记可信验收命令。模型可以实现功能，但不能修改验收基础设施来伪造通过。
2. 配置实际账号支持的模型 ID；经济、常规、强档位由项目任务范围与失败升级规则选择。Codex 工作线程固定使用 medium effort，避免继承维护者个人的 ultra 设置。
3. 先运行只读探针，再做一个有具体验收的真实交付。安装成功、检测到登录来源、只读探针通过和工程交付通过是四种不同证据。
4. 设置项目自主模式和允许的风险。当前文本风险规则仍保守，业务文案中的“安全”“登录”等词可能需要较高风险授权；模型自己写“低风险”不能绕过项目策略。
5. Codex 订阅调用可能没有美元费用字段。若允许有界继续，仍按真实 token 额度、任务数、并行数、阶段超时和尝试次数控制；未知美元费用不能写成零，也不会自动发布。
6. 一般任务检查失败按项目次数修复/升级。各任务集成后检查失败，可在原声明文件范围内做一次额外集成修复，并重跑全部可信检查。失败现场、取消和费用不足保留真实状态。

已发生写入的中断不会在重启时盲目再跑：系统保留工作树与检查点供核对。需求、只读规划和未执行队列可以按恢复策略继续。

Codex 后台进程单独关闭应用连接器和插件，逐项禁用读取到的个人/项目 MCP 配置；这些覆盖只作用于该次子进程，不修改用户配置或登录身份。模型派发前读取实际配置和 MCP 状态，确认没有可用的外部 MCP 工具。当前代码任务使用原生文件与命令工具，工作说明由工厂组装。后续接入飞书、云资源等能力需要工厂明确提供连接器，不能借用维护者桌面的隐式连接。

长任务通过 SDK 公共事件流记录工具开始、完成、输出摘要和用量；不保存内部推理，不逐字复制流式文字来充当进度。日志出现工具活动不代表任务已完成，完成以可信检查和交付状态为准。

后台同时剥离桌面进程的内部连接信息以及 shell 的 `_` 变量。后者在本机启动链中可能携带无效编码并导致 SDK 命令崩溃；正常 Unicode 路径、认证及代理环境保持可用。此问题已通过实际中文目录中的随机文件读取验证。

## 本机连接排查

macOS 系统代理不一定被命令行 SDK 继承。运行配置会提示系统启用代理而进程未配置代理的情况；它不会修改网络设置或把此提示当成连接测试。本机本轮实际验证需要在服务进程环境配置现有代理：

```bash
HTTPS_PROXY=http://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897 \
  .venv/bin/factory-web serve --port 8788
```

上面的地址是本机已存在的代理，不是所有部署的通用地址。不要复制代理凭据到项目文档。Provider 子进程继承必要的认证与网络环境，发布密钥仍由控制平面保留。

## 可重复的真实验收

`scripts/verify_live_factory.py` 只在明确传入 `--execute` 时使用真实 Provider。它创建隔离仓库、可信工单路由检查、独立成员与额度，运行两项有依赖的代码任务，保存 `result.json` 和完整 `evidence.json`。不发布 PR、不部署、不修改用户项目。

```bash
HTTPS_PROXY=http://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897 \
  .venv/bin/python scripts/verify_live_factory.py --execute \
  --model gpt-5.6-luna --worker-model gpt-5.6-terra --max-risk high --timeout 600
```

模型 ID 需与实际账号一致。此样例包含“安全事件”的业务字段，保守风险规则会标记高风险，故显式授权这个隔离项目的范围。此授权不改变其他项目，也不能当作复杂客户项目已经无人交付的证明。

如只需验证模型工具确实能读文件，可显式运行 `scripts/verify_live_commands.py --execute --model <模型 ID>`。它创建随机内容和独立额度账本，要求实际命令成功且模型返回匹配内容；这也是一次真实模型调用，正常使用不需要反复执行。

供应商口径依据：[OpenAI 的订阅与 API 计费区别](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)、[Claude 输入与缓存 token 的构成](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)。实际 SDK 字段以仓库安装版本的类型定义与测试为准。
