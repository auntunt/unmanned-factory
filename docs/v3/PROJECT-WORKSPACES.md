# 项目工作台与待处理运行

工程总览按项目展示六阶段入口。各项目的需求、方案、任务、检查、交付与来源能力分别汇总；全局页保留整个工作区的数量与待处理事项。

## 从项目进入对应内容

- `/projects/{id}?stage=intake`：原始需求、澄清问题与需求入口。
- `stage=plan`：已有方案、任务分工和依赖。
- `stage=build`：实际任务与模型尝试。
- `stage=verify`：集成、任务和尝试产生的检查结果。
- `stage=deliver`：已记录提交、交付分支和发布证据。
- `stage=reuse`：来源属于本项目的能力；跨项目绑定在“自主策略与能力”管理。

阶段按已经保存的证据展示，不再按当前运行状态互斥分桶。暂停不会清空之前的阶段；有计划也不能据此推断已经开发或通过验证。点击阶段产出进入相应 `?view=requirements|plan|execution|verification|delivery` 运行视图。

`GET /api/v3/overview?project_id={id}` 与 `GET /api/v2/runs?project_id={id}` 在服务端限定项目；不存在的项目返回 404。需求列表按项目筛选后读取，避免全局近期记录挤掉其他项目。已有小组共享阅读权限保持不变，项目范围不是新增的租户权限隔离。

## 明确停止原因和预算入口

列表、项目待处理区和运行详情共用状态指引，区分需求补充、批准计划、预算停止、费用未知、执行失败与恢复暂停。没有问题时，不把预算或执行异常展示为需要填写需求的表单。历史失败已修复的运行不继续计入待处理。

预算停止时，管理员可点“调整项目预算”，直接定位：

`/projects/{id}?tab=settings&return_run={run_id}#project-budget`

保存后可返回原运行，再点“按新配置重试”。原运行保留当时的预算及停止记录；修改项目设置不会自动继续旧运行，不会产生新的模型调用。已有项目忙碌时禁止修改设置的服务端约束仍保留。

配置分为三个明确入口：

- 项目“预算与设置”：每次运行的美元费用停止线。
- “团队与额度”：成员、项目、工作区的月度 token 额度。
- “运行配置”：工作区共享的模型分档和未知美元费用策略。

## Auto 模式与版本记录

未保存过执行策略的项目默认使用 Auto（最高中风险，每项两次尝试）；显式保存的监督策略继续生效。Auto 对来源可信、需求与验收完整、符合风险范围的计划自动授权，仍执行预算、额度、代码基线、检查及模型配置校验。

项目页常驻显示执行方式，“Auto 与能力”可修改版本化策略。保存 Auto 时可勾选接续当前待批准计划：后端在协调锁内保存策略并重新核对 waiting 计划；通过后沿用原计划版本排队，记录采用前后的策略与授权依据。正在执行、超额或失败的运行不被批量恢复。该操作不会重新调用规划模型。

运行页显示实际冻结策略，等待原因区分监督模式与自动策略未覆盖。允许操作的成员可在待执行或暂停状态补充要求，生成下一版计划；预算及费用暂停保留配置处理入口。计划版本从专用只读接口按需加载最近 100 个保存版本，保留摘要、范围与验收条件。已执行代码使用独立分支和提交保留；当前没有页面内一键 Git 回滚，修改通过后续需求或 Git revert 完成，已消耗额度不会因代码回退恢复。

## 废弃记录与数据刷新

暂停、失败或等待处理的旧运行可以标记为“已废弃”。该动作只把记录移出当前待办，不删除计划、费用、日志、工作区或导出证据；运行详情保留废弃前状态和操作事件。废弃记录继续出现在“异常与取消”历史筛选中。

所有只读 API 请求显式绕过浏览器缓存，服务端继续返回 `Cache-Control: no-store`。工程总览、项目工作区和运行看板在窗口重新获得焦点、页面重新可见以及同源标签页发生数据变更时立即重新读取；定时刷新作为兜底。运行状态动作完成后会广播数据变更，避免其他页面继续展示旧待办。
