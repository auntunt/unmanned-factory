# MFD → 江苏标准 XML：真实样本提取核对报告

2026-09-17 · 职能包 `MFD → 江苏标准 XML（清单局部提取）` · 由逆向工程职能体基于已有样本、
逆向笔记与江苏未来数据标准 XSD 开发，本机**没有**现成转换器源码。

本报告只写结论与校验值。真实工程样本与甲方参考 XML **不进仓库**（含工程造价业务数据）。

## 1. 样本

| 项 | 值 |
|---|---|
| 文件 | `2.mfd`（江苏未来计价 Mars，项目“定额-简易”） |
| sha256 | `ebfeec1212b05b8caced2c5eea8204320734175109220ee3a4a2c6c9e358c08c` |
| 字节数 | 58,528 |
| 记录流起点 | `0x403`（0x400 处 varint tag=0x03 → 2 字节载荷 → 流始于 0x403） |

核对用的甲方参考 XML 同目录存放，**只用于事后核对，没有任何业务值从它流入解析结果**。

## 2. 真实转换结果（在隔离运行时中执行，非 mock）

```
records_total 14  records_emitted 2  records_unresolved 12  complete false
tokens 6698       bytes_not_interpreted 29754
status failed / error_code incomplete_extraction
```

`bytes_not_interpreted` 是未被任何已确认词素消费的字节数。**它不是完整度指标**——
本工具做的是局部词法扫描，不做整体分帧。

## 3. 与参考 XML 的一致性（逐条核对）

| 维度 | 结果 |
|---|---|
| 清单记录条数 | 14，与参考 XML 的 14 条完全一致 |
| 编号序列 | 14/14 逐条一致（顺序也一致） |
| 名称序列 | 14/14 逐条一致 |
| 单位 + 工程量/单价/合价 | 2/14 完整提取且逐值一致；其余 12 条判为缺失 |

完整提取的两条：

| 偏移 | 编号 | 名称 | 单位 | 工程量 | 单价 | 合价 |
|---|---|---|---|---|---|---|
| `0xf65` | 010101002001 | 挖一般土方 | m3 | 1.0 | 502.92 | 502.92 |
| `0x18ad` | 011707001001 | 安全文明施工 | 项 | 1.0 | 3949.57 | 3949.57 |

`0x18ad` 的单价在 MFD 中存的 double 是 `3949.5699999999997`；XML 里的 `3949.57` 来自
**声明过的 2 位小数 ROUND_HALF_UP 归一**（金额以分为单位），原始 double 同时写进
`extraction_report.json`。这不是从参考 XML 回填。

未完整提取的 12 条（全部为技术措施清单）的偏移：`0x1be5 0x1c9b 0x1d57 0x1e15 0x1ede
0x1fa4 0x205d 0x2113 0x2211 0x22cb 0x2391 0x2455`，缺 `单位/工程量/单价/合价`。
参考 XML 里这些记录确有单位与数值，但本工具**没有**在已确认文法内定位到它们，
因此按缺失输出，不写进 XML。

## 4. 对逆向笔记的一处修正

《MFD 格式逆向工程总结》§4.3 把 `04 08 06 <len> <data>` 记为 **ASCII 字符串**。
实测该槽位承载 **GBK**：`0xf7a` 处 `cd da d2 bb b0 e3 cd c1 b7 bd` 解 GBK 得「挖一般土方」，
与参考 XML 的名称一致。按 ASCII 过滤会把全部中文名称丢掉——最初的扫描正是这么丢的。
词法层因此改为按 GBK 解码，解不出则保留十六进制并标记 `undecoded`，不做替换字符糊弄。

## 5. 明确的缺口

1. **整体分帧未打通**：容器只带子节点个数、不带字节长度，上游逆向仍停留在个位数百分比。
   本包不做也不声称。
2. **技术措施记录的单位/数值字段标签**缺少跨样本证据（单样本推断会过拟合）。
3. **工程信息、费用汇总表、工料机汇总、定额层级**未提取。
4. **只有一对样本**（2.mfd / 参考 XML）。多样本回归、大文件、加密与截断样本都没有覆盖。
5. **XSD 内容模型校验未做**：现有 `fixtures/fidelity_check.py` 是受限的词表符合性 + 字段值对比，
   不等于完整 XSD 校验（需要 lxml）。

## 6. 结论

可以诚实声称的是：**从真实 MFD 字节中提取出了与甲方参考 XML 完全一致的 14 条清单编号与名称，
其中 2 条的单位与金额逐值一致，并生成了对应的江苏标准 XML 子集。**

不能声称的是：无损转换、完整转换、对其他 MFD 变体可用。职能包的 `support_matrix`
按上述边界逐条写明，验证证据绑定候选内容摘要。
