## 1. 这个系统是什么

它不是编码 agent。它是**架在编码 agent 上面的判收层**：

```
任务来源（口述 / PRD / backlog）
        ↓  intake：抽取、拆分、反推 check、入口闸门
   派发（dispatcher）→ 编码 agent（Claude Code，跑在 seatbelt 沙箱里）
        ↓  拿到 diff
   判收：13 道确定性闸门（+1 道故障判定）+ 4 类监工 + A/B/C/D 分级
        ↓
   A/B 类 → 自动落地（commit）    C 类 → 升级给人    D 类 → 硬闸门拦死
        ↓
   审计（SQLite）→ 指标 → 看板
```

一句话的差别：代码审查工具产出**建议**，可观测工具产出**记录**，这一层产出**裁决** —— 它会拒绝合并。

## 3. 判收链路

### 3.1 分级（A/B/C/D）

分级引擎跑**两次**：派发前按声明路径预判，拿到 diff 后按真实改动文件重判，变差就升级。规则在 `factory/grading/oracle_rules.yaml`。

- **A/B 类** —— 无人，自动落地
- **C 类** —— 升级给人看
- **D 类** —— `blocked_hard_gate`，硬闸门拦死，不给合

两次分级的意义：worker 声明改 `src/`，实际动了 `auth/`，第二次分级会抓到。

### 3.2 四类监工

| 监工 | 性质 | 能否否决 | 成本 |
|---|---|---|---|
| 回归（regression） | 确定性、fail-closed | 能 | $0 |
| 范围（scope） | 确定性 | 能 | $0 |
| 规格（spec） | 模型 | 能 | 有 |
| 架构（architecture） | 模型 | **不能** | 有 |

架构监工出的是**意见不是证据**，没有客观裁判能证明它对。让意见能否决合并等于给一个爱挑刺的监工一票否决权，每个任务都能被拖到三轮上人 —— 那条"上人平均打回次数 ≤ 1"的判据当场就废。所以它的意见前两轮当返工建议带回去，最后一轮不再拦，照样入库留证。

### 3.3 13 道确定性闸门（+1 个故障信号）

全部是 `_review` 里的 early-return，全部报 `SupervisorRole.REGRESSION`，全部零模型成本：

| 闸门 | 拦什么 |
|---|---|
| `diff` | diff 为空或读不出来 |
| `git-hook-touched` | worker 动了 git hooks |
| `shadow-code` | 被 gitignore 藏起来的新代码 |
| `runner-hook-added` | 新增 runner 自动加载文件（自己出卷子） |
| `diff-suppressed` | `.gitattributes` 把 diff 正文压掉 |
| `index-skip-flag` | 索引跳过标记让改动从 git 眼里消失 |
| `git-config-touched` | `.git/config` 能把 diff 变成空字符串 |
| `info-attributes-touched` | `.git/info/attributes` |
| `head-moved` | HEAD 被移动，未审代码藏进历史 |
| `replace-refs-changed` | `refs/replace` 让 git 在对象内容上撒谎 |
| `gitlink-added` | mode-160000 把代码藏进 git 不展开的盒子 |
| `spec-criteria-mutated` | worker 改自己的验收标准 |
| `fake-green` | 金丝雀探针验出这份绿推不翻 |

`dispatcher.py` 里的 `_blocked()` 名字实际有 **14** 个，第 14 个是 `harness` —— 它**刻意不算闸门**，在 `dashboard.py` 里单独放进 `FAULT_CLAIMS`。理由是一次真跑批：网关回了个 502，attempt 记成 `reworked` + 红色「闸门 harness」，于是一条**处理得完全正确**的链路（打回 → 重试 → 合并）在页面上长成「模型写错了、被闸门拦下」——读者读到的两件事都不成立。第二个理由是那张命中率表：harness 混在里面会让「闸门拦下 N 次」掺进一堆 502，而虚高的方向恰好**对我们有利**，这种偏差没人会来纠。所以两张表不许合并，否则「闸门拦下」和「工具坏了」就只剩一个计数器。

### 3.4 八条基线

闸门要判"这一轮才被关掉"，就必须有轮次开始前的快照。八条基线全部在轮循环**外面**取，且**都没有默认值** —— 漏传的调用方会直接抛错，不会拿一个 `frozenset()` 去猜。

理由写在 `dispatcher.py` 的 docstring 里：给基线填空默认值，会让一个本来就装了合法 pre-commit 的仓库上每个任务都判红。而**恒红和恒绿一样是坏的，但恒红会被人当成闸门有毛病，比恒绿更快被拆**。

八条：hooks、criteria、skipped、config、attrs、head、replaces、gitlinks。

## 4. 副作用隔离

用 macOS **seatbelt**（`sandbox-exec`），不用容器。Docker 在本机可用，仍然不选。

理由：这一层要隔离的是**文件系统副作用**，不是完整运行时。容器要挂卷、要同步 git 状态、要处理 uid 映射，每一样都是新的"看起来隔离了其实没有"的面。seatbelt 是内核级路径判定，规则文件本身可读可审。

代价是**不管网络** —— 明确写进边界，不假装它管了。

一个实测的边界细节：工厂根在 `denied` 里，但那只是 **deny write**。沙箱里 `cat verdict_probe.py` 是 `rc=0`，常量看得见。真正的防护来自"在外部项目上跑时工厂源码不在 workspace 里"，加上 `ps` 在沙箱下被拒，argv 读不到工厂路径。

## 5. 审计与指标

- **存储**：SQLite，`create_all`，P0 不做 migration
- **脱敏**：`factory/redact.py`。`redact()` 在 `AuditStore.record_verdict` 里施加，不在各个监工里 —— claims 直接来自 check 的 stdout/stderr，是**唯一可能携带明文密钥的入口**。理由和 D 类硬闸门同一条：**不留旁路**。
- **口径**：`hit_rate` 在分母为 0 时返回 `None` 而不是 0；`cost_per_hit` 同理。0 和"没数据"必须能分开。
- **漏账熔断**：连续 2 次记不上账就停机。被 kill 的进程不报花费，$5 默认上限在那条路径上形同虚设，所以给"假的价格"单独设了上限。
- **看板**：`factory dashboard`，只绑 `127.0.0.1`，**没有认证**，启动横幅明说了。要给远程的人看用 `--once out.html` 导出。

## 6. 核心资产：19 个洞

这是这套系统最不可复制的部分。每一个洞都是**编码 agent 交出一份看着是绿的东西、实际不是**，而且都是攻自己的闸门攻出来的。

git 历史里有明确编号的到第十八个，今晚又找到第十九个。

| # | 洞 | 机制 |
|---|---|---|
| 1-11 | 早期批次 | 超时漏账、孤儿进程、监工输入结构/视野/输出前缀、判据本身、格式漂移、静默降级 |
| 12 | 索引跳过标记 | `assume-unchanged` / `skip-worktree` 让 `changed_paths` 里没有它，check 却跑在真实树上 |
| 13 | `.git/config` | 能把监工看到的 diff 变成空字符串，且两条路都不碰被跟踪文件 |
| 14 | config 第四层 | 落在第十三道闸门的视野外 |
| 15 | `.git/info/attributes` | 让第七道闸门的基线和现状**同时**坏掉 |
| 16 | HEAD 被移动 | 盯了 `git diff HEAD` 的输入，忘了 HEAD 本身；判据必须是 (哈希, ref) 对 |
| 17 | `refs/replace/*` | 让 git 在"对象是什么"上撒谎，diff 变空或藏掉全新文件 |
| 18 | gitlink (mode 160000) | 第一个不攻 git 而**顺着规矩走**的洞：`git init evil/` → 索引里一行 gitlink，12 道闸门全静默，pytest 却会执行 `evil/conftest.py` |
| 19 | 金丝雀落点（本次发现） | 见下 |

### 6.1 第十九个洞：诱饵目录

今晚发现，比它旁边那个更严重。

金丝雀探针的作用是验"这份绿推不推得翻"：往测试目录写一个必然失败的测试，check 应该变红；不变红说明这份绿是假的。落点由 `canary_target()` 决定，它按 `_TEST_DIRS = ("tests", "test")` 取**第一个存在的目录**。

攻击：测试真放在 `test/`（单数）的仓库里，worker 改 `test/conftest.py` 伪造绿，同时 `mkdir tests`（空目录）。

- 金丝雀落进那个**空的诱饵目录**，pytest 压根不收集它
- 探针返回 `skipped=False, fake_green=False` —— 不是"没验"，是**主动报告"验过了，这份绿是真的"**
- 触发物是一个空目录，**git 不跟踪空目录**，`changed_paths`、`added_paths`、diff 里一个字都没有
- 不需要读任何工厂常量，`tests` / `test` 就是最自然的两个猜测

**bug 只有一行。** `_TEST_DIRS` 自己的注释写着「必须放进**已经有测试**的目录」，并解释了原因（pytest 的 `testpaths` / `--ignore` 可能压根不看它）。但 `canary_target()` 只判 `d.is_dir()`。**声明的判据从来没被实现。**

同一片区域还有一个较弱的变体：worker 直接造一个和金丝雀同名的文件（`CANARY_NAME` 是硬编码可读常量），撞名出口静默跳过，探针永久失效。这条**会出货** —— 该文件本身在 `changed_paths` 里，属于审过的那一组，所以 `land` 真的会提交它。由此可以做成两阶段：任务 1 合法地"加了个测试"（没有任何闸门有理由拦），合进主干后，往后每个任务的金丝雀都失效，第二个 worker 甚至不必知道这件事 —— 植入和利用在两条不同的审计记录里。

### 6.2 反复出现的形状

这些是跨多个洞重复出现的结构性教训，比单个洞更有价值：

1. **静默降级永远更好看** —— 出错的方向总是朝"成功且免费"，所以必须 fail-closed
2. **一道闸门的基线可能落在另一道闸门的下游** —— 同一形状撞了三次
3. **测接线，不只测行为** —— 一道谁都没接上的闸门，在报表上和接上了长得一样
4. **空基线让接线测试瞎掉** —— `!=` 和"条数变多"在空基线上无法区分
5. **闸门的时刻，不只是接线** —— 基线每轮重取 = 只拦第一轮，单元测试对它完全免疫
6. **验效果，不猜机制** —— 金丝雀能穿透三种伪造绿，误拒率比猜机制还低
7. **检查员不许写它检查的那个仓库**
8. **先变异再写测试** —— 顺序反了会往仓库加一条永远不会失败的断言

## 7. 方法论：变异测试

这套系统的测试可信度靠**变异测试**保证，不靠覆盖率。规程是从一次真实事故里长出来的：

1. **所有 assert 提到备份之前** —— 脚本的作用就是"扑空要炸"，那它炸的时候仓库必须还没被动过
2. **一个脚本只做一处改动** —— assert 夹在两次 replace 中间会让改动**整批丢失**，而症状会伪装成"被测代码的某个特性"
3. **断言子串存在，且计数为 1** —— 只判 `in` 挡不住同一子串出现两次
4. **三步收尾**：diff 与备份一致 → 删备份 → grep 确认变异串计数为 0

那次事故的价值在于它的症状：assert 确实炸了，但炸在 `finally` 恢复**之前**，于是 `workspace.py` 停在变异体上，而测试文件报告 18 passed —— 一个**变异前**的结果。第一反应是去"修实现"，那等于**把变异体当成品提交**。所以现在的判断顺序是：先看有没有 `.bak` 残留，再谈实现对不对。

## 8. 与相邻品类的关系

| 品类 | 代表 | 产出 | 和这一层的关系 |
|---|---|---|---|
| 编码 agent | Claude Code / Devin / Cursor | diff | **底座**，被消费 |
| AI 代码审查 | CodeRabbit / Greptile / Qodo | PR 评论（建议） | 人仍然做决定 |
| Agent 可观测 | Langfuse / Braintrust / LangSmith | 记录 + 事后打分 | 记账，不设闸 |

那三类都不做的一件事是**拒绝合并**。也因此，第 6 节那 19 个洞是审查类工具结构上产不出的发现 —— 它们没有一个"会被骗"的验证器。

## 10. 取数命令

```bash
# 代码行数
find factory -name '*.py' | xargs wc -l | tail -1
find tests   -name '*.py' | xargs wc -l | tail -1

# 测试函数数
grep -rho "^def test_\|^    def test_" tests/*.py | wc -l

# 离线全套（必须排除 smoke，否则会真调模型 CLI，约 6 分钟、$0.5–$2.5）
uv run pytest -m "not smoke"

# dispatcher 的 14 个 _blocked() 名字（多行调用，正则必须容忍换行）
# 14 ≠ 闸门数：其中 harness 是「工具坏了」这个故障，不是闸门（见 §3.3）。
# 闸门是 13 道。判两表一致要拿 GATE_CLAIMS | FAULT_CLAIMS 去比这 14 个名字。
python3 -c "
import re,pathlib
s=pathlib.Path('factory/dispatcher.py').read_text()
print(sorted(re.findall(r'self\._blocked\(\s*\n?\s*\"([^\"]+)\"', s)))"

# 洞的编号
git log --oneline --all | grep -i 洞
```

注：抽这 14 个名字时，**单行 grep 会静默返回空** —— `self._blocked(` 和名字字符串不在同一行。这本身就是本报告 §6.2 第 1 条的一个实例。

再注：这条命令返回 **14**，闸门却是 **13** 道，差的那个是 `harness`。把命令的返回值直接当闸门数写进文档，正是 `dashboard.py` 里那段注释警告的错 —— **本报告的上一版就是这么写的**，而且错的方向（闸门看起来更多）恰好对我们有利。
