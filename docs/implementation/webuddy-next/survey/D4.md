# D4 配置归管理员 — 现状调查（只读，基线 6fe1883）

## 角色与鉴权现状（含后端强制点）

### 后端中间件层（全局写操作守门）
- `factory/control/app.py:230` — 所有非 GET/HEAD/OPTIONS 的 API 请求，如果 `user['role'] != 'admin'`，则进入白名单判断。不在白名单的写操作一律返回 403「此操作需要管理员权限」。
- 白名单仅包含：自有账号操作（logout/password）、自己发起的 run 上的动作（clarify/continue/approve 等，且 actor_id 必须匹配）、以及在已分配项目上创建 run。
- **结论：所有配置类写接口（PUT/POST deploy-targets、runtime/profiles、runtime/operations、team mutations）对 member 角色由中间件统一拦截，后端强制。**

### 路由层二次确认（双保险）
- `factory/control/remote_routes.py:43-44` — deploy-targets 所有端点（GET 含）都显式调用 `admin(request)`，member 访问列表也返回 403。
- `factory/control/runtime_routes.py:55` — `GET /api/v2/runtime/operations` 显式检查 admin，member 返回 403。
- `factory/control/team_routes.py:1` — docstring 标注 "all mutations require admin at boundary"。成员管理/额度/核对/设置全部由中间件拦截。
- `factory/control/app.py:331` — `GET /api/v2/project-candidates` 显式检查 admin。

### 前端层
- `frontend/src/workbench/Workbench.tsx:29` — member 角色不显示 `secondaryNavigation`（运行配置入口），admin 可见。仅前端隐藏，**但后端 GET /api/v2/runtime 本身无 admin 检查**（见下方缺失）。
- `frontend/src/workbench/ServerTargets.tsx:63-74` — `ProjectTargets` 组件根据 `isAdmin` prop 决定是否显示绑定管理和完整目标列表。member 仅能看到 `bindings.available`（已绑定到该项目的目标名/id），不能访问全目标列表。
- `frontend/src/workbench/TeamPage.tsx:23,68` — 根据 `isAdmin` 切换 readonly 视图。额度与成员管理只有 admin 看到编辑 UI。

### 项目级权限
- `factory/control/governance.py:81-86` — `require_project` 检查用户是否有项目执行权限（admin 直接通过，member 需查 team_projects 表）。
- `factory/control/remote_routes.py:95` — `GET /api/v2/projects/{pid}/deploy-targets`（项目绑定查询）走 `governance.require_project`，member 只要有项目权限就能读到该项目已绑定的目标名/id（不含私钥和详细配置）。

## 部分实现 / 需要修复

- `factory/control/runtime_routes.py:68-70` — `runtime()` 无任何角色检查。
- `inspect_runtime` 返回 profiles（provider + model ID）、limits、tools 诊断、auth_sources 列表、host 信息、blockers 等。

- **低风险**：中间件已拦截。建议增加显式检查。

## 缺失（需要新增）

### M1: 普通用户「能不能用 / 能不能部署」专用视图
- **现状**：member 在前端看不到运行配置入口（导航隐藏），但可通过直接访问 `GET /api/v2/runtime` 拿到完整配置。没有专门的「我的项目能不能部署」接口。
- **需要新增**：`GET /api/v2/runtime/status`（或将 `GET /runtime` 按角色裁剪返回），返回三个布尔值 `{ planning: bool, execution: bool, publishing: bool }` 和 blockers 列表，不含 profiles、tools 详情。
- **前端**：member 在项目页或开始页能看到「当前平台可用 / 不可用」指示。

### M2: 管理员配置对话
- **现状**：管理员配置只有表单入口（RuntimePage、OperationsSettings、ServerTargets、TeamPage），没有对话式配置界面。
- agent conversation 系统（`factory/control/conversation_tools.py`、`agent_routes.py`）已有对话+任务调度能力，但不支持「管理员通过对话配置 runtime/deploy-targets/operations」的场景。
- **最小差距**：
  - 后端：对话工具模块 `conversation_tools.py` 需要新增 admin-only 配置工具（例如 `update_runtime_profile`、`update_webhook`、`manage_deploy_target`），这些工具内部调用与表单相同的 `RuntimeSettings.update()`、`OperationsAutomation.configure()`、`TargetStore.create/update/delete()`。
  - 已有可复用的后端方法：`RuntimeSettings.update()`（`runtime.py`）、`OperationsAutomation.configure()`（`operations_automation.py`）、`TargetStore.create/update/delete()`（`deploy_targets.py`）。这些方法已独立于 HTTP 路由，可被对话工具直接调用。
  - 缺失：对话工具注册、admin 身份绑定到对话上下文、结构化输出 schema 定义。
  - 不需要新增 HTTP 端点——对话工具走 MCP session server 通道（已有基础设施）。

## 密钥链路核实（存储位置 / 脱敏出口 / 是否触达模型）

### 存储位置

| 密钥类型 | 存储位置 | 参考 |
|---------|---------|------|
| SSH 部署私钥 | `FACTORY_DEPLOY_KEY_DIR/<target_id>`，0o600 权限，专用目录 | `deploy_targets.py:121-124` |
| SSH 部署公钥 | SQLite `deploy_targets` 表的 JSON data 字段 | `deploy_targets.py:118` |

| 用户密码 | SQLite `users` 表，bcrypt 哈希 | `auth.py:177` (推断) |
| session/csrf token | SQLite `sessions` 表 | `auth.py:293-294` |

### 脱敏出口

1. **AuditStore 写入边界** — `factory/audit/store.py:220-222` 对 claims 调用 `redact()`。`factory/audit/store.py:265` 对 resolution_note 调用 `redact_text()`。
2. **Store.scrub()** — `factory/control/store.py:22-42` 双层脱敏：先 `redact_text()`（regex 模式匹配），再扫描环境变量中含 TOKEN/PASSWORD/SECRET/API_KEY 的值做字面替换。
3. **providers._safe_json()** — `factory/control/providers.py:247-274` 对 JSONL 控制通道脱敏，api_key/access_token/refresh_token/secret/password/authorization 字段值替换为 `<redacted>`。
4. **redact.py 模式覆盖** — `factory/redact.py:17-45` 覆盖：飞书 webhook URL、key=value 格式的密码/token/api_key/secret 等、Authorization header、sshpass/--password 参数、供应商前缀裸 token（sk-ant-、sk-、ghp_/ghs_/ghr_/gho_/ghu_、AKIA、xox-）、PEM 私钥整块。
5. **deploy_targets 命令校验** — `deploy_targets.py:101` 调用 `scrub(v) != v` 检查：如果预注册命令文本包含可识别的密钥模式，创建/更新直接拒绝。
6. **remote_targets 输出脱敏** — `remote_targets.py:122,149,233` 对远程执行输出和异常调用 `redact_text()`。
7. **operations_automation webhook** — `operations_automation.py:73` 返回给前端的 config 只含 `webhook_configured: bool`，不含 URL。
8. **runtime auth_sources** — `runtime.py:383-401` `_auth_sources()` 注释明确 "without opening them or showing paths"，只返回 "environment" / "credential_file" 字符串。

### 是否触达模型

1. **Provider 凭据（ANTHROPIC_API_KEY 等）** — 在 worker 进程环境中存在（`providers.py:171` 注释 "Provider credentials intentionally remain available because SDK authentication is provider-owned"），用于 SDK 认证。模型不通过 prompt 接收这些值。但 worker 进程环境中有这些变量，模型通过 Bash 工具理论上可以 `echo $ANTHROPIC_API_KEY`。
   - **缓解**：permission 系统 + PreToolUse hook（`providers.py:568-585`）控制工具访问；但 T10 发现 user settings 的 hooks/permissions/env 会一并加载。
   - **风险评估**：中等——依赖 permission policy 和 sandbox，不是结构性隔离。

2. **FACTORY_GITHUB_TOKEN / FACTORY_WEBHOOK_SECRET** — 被 `_STRIPPED_ENV_KEYS`（`providers.py:176-177`）和 `_worker_env()`（`providers.py:1395-1406`）从 worker 进程环境中剥离。模型进程不可见。

3. **SSH 部署私钥** — 存储在 `FACTORY_DEPLOY_KEY_DIR`，worker 进程（sandbox 内）不知道该目录。`deploy_keys.py:15-16` 检查 key dir 不与 workspace 重叠。`remote_targets.py:1` docstring "no credentials or command text cross into agents"。模型不可见。

4. **飞书 webhook URL** — 存储在 `operations.json` 文件中，不在 worker 可访问路径内。`redact.py:18` 第一个 pattern 覆盖飞书 webhook URL 格式。前端仅显示 `webhook_configured`。模型不可见。

5. **system_prompt** — `providers.py:630-680` 构造的 system_prompt 不含任何密钥引用。append 内容是工作指令文本。

6. **run 上下文/事件** — `store.py:22-42` 的 `scrub()` + `redact_text()` 应用于所有落库的事件数据。`_safe_json()` 应用于 JSONL 控制通道。

**结论**：密钥不通过 prompt/system_prompt 触达模型。provider 凭据在 worker 进程环境变量中存在（SDK 认证需要），模型可通过 Bash 工具读取——依赖 permission/sandbox 防护，非结构性隔离。其他密钥（GitHub token、webhook URL、SSH 私钥）均已从 worker 环境/路径隔离。

## 不确定 / 需要主会话裁决

1. **GET /api/v2/runtime 是否应对 member 限制**：当前任何已登录用户可读完整运行配置（profiles、tools 诊断、host info）。如果 D4 要求"普通用户只看能不能用"，需要明确是拆分端点还是按角色裁剪返回。
2. **管理员配置对话的优先级**：表单路径已完整可用。对话路径需要新增约 150-250 行。如果 v-next 不含对话式配置，可标为 P2/P3 延后。
3. **provider 凭据在 worker 环境的结构性隔离**：当前靠 permission + sandbox，T10 已记录风险。是否需要在 v-next 做进一步隔离（例如 credential proxy / token broker）需裁决。
