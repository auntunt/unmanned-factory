## 完成行为

### POST /api/v4/sessions/{sid}/skills 扩展

同一端点按 Content-Type 分流：

- `multipart/form-data` + file → ZIP 导入（N3 既有，不变）
- `application/json` + `origin: "github"` → GitHub 拉取（N4 新增）

**GitHub 请求体**：
```json
{
  "origin": "github",
  "owner_repo": "owner/repo",
  "ref": "main",
  "subpath": "skills/my-skill"
}
```

**响应**（201）：与 ZIP 来源同一 JSON 形状，`origin: "github"`，`source_version` 为 40 位 commit SHA。

**错误**：422 携带 `{message, reason}` 结构化错误。

### 拉取层

`factory/control/github_skill_fetch.py`：

- `GitHubSkillFetcher`：构造时可注入 `httpx.Client`（测试）或通过 `FACTORY_GITHUB_TOKEN` 认证
- `resolve_commit_sha`：分支/标签/SHA → 40 位 commit hex（先试 SHA 媒体类型，回退 JSON）
- `fetch_skill_md`：通过 Contents API 拉取 SKILL.md，支持子路径
- `_parse_skill_content`：与 ZIP 路径共用的 frontmatter 解析逻辑
- `GitHubSkillFetchError`：结构化错误，携带 `reason` 字段（`invalid_repository` / `repo_not_found` / `auth_invalid` / `access_denied` / `skill_not_found` / `invalid_skill_format` / `api_error` 等）
- fetcher 通过 `app.state.github_skill_fetcher` 注入路由（测试替换，生产按需创建）

### 存储层

`SessionSkillStore.create_from_github(session_id, FetchResult, actor_id)`：
- 将 `FetchResult.commit_sha` 写入 `source_version`（保证 40 位 SHA）
- 将 `FetchResult.source_ref` 写入 `source_ref`（保留原始引用）
- 自动推导 `dependency_state`：有依赖 → `missing`，无依赖 → `ready`
- 底层复用 `create_from_data`，不改表结构

## 真实验证

**目标**：公开仓库 `octocat/Hello-World`（无 token）

| 步骤 | 结果 |
|------|------|
| `resolve_commit_sha('octocat/Hello-World', 'master')` | 成功 → `7fd1a60b01f91b314f59955a4e4d4e80d8edf11d` |
| `fetch_skill_md` 对无 SKILL.md 的仓库 | 正确返回 `skill_not_found` |
| Contents API 拉取已有文件 | 正常工作（type=file, size=13） |

## N5 接线指南

### 前端 GitHub 导入

```javascript
// POST JSON body（不是 multipart）
const resp = await fetch(`/api/v4/sessions/${sid}/skills`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', ...authHeaders },
  body: JSON.stringify({
    origin: 'github',
    owner_repo: 'owner/repo',
    ref: 'main',           // 可选
    subpath: 'skills/foo', // 可选
  }),
});
```
