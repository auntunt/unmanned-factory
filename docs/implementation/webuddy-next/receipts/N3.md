## 表结构

```sql
CREATE TABLE IF NOT EXISTS session_skills(
    id TEXT PRIMARY KEY,
    session_id TEXT NOT NULL,
    data TEXT NOT NULL,
    created_at TEXT NOT NULL);

    ON session_skills(session_id);
```

## 路由

### `POST /api/v4/sessions/{sid}/skills`

导入并绑定到该会话。

**请求**：`multipart/form-data`，字段 `file`（ZIP 文件）
**响应**（201）：
```json
{
  "id": "abc123",
  "session_id": "sess-aaa",
  "name": "test-skill",
  "origin": "zip",
  "source_ref": "SKILL.md",
  "source_version": "1.0",
  "source_sha256": "deadbeef...",
  "entry": "SKILL.md",
  "description": "A test skill",
  "dependencies": [],
  "import_state": "imported",
  "dependency_state": "ready",
  "actor_id": "user-1",
  "created_at": "2026-09-19T00:00:00+00:00"
}
```
**错误**：404（会话不存在）、422（包格式非法或超限）

### `GET /api/v4/sessions/{sid}/skills`

列出该会话所有绑定。

**响应**（200）：
```json
{
  "items": [
    { "id": "...", "name": "...", "origin": "zip", ... }
  ]
}
```
**错误**：404（会话不存在）

### `DELETE /api/v4/sessions/{sid}/skills/{id}`

解绑。已产生的 run snapshot 不受影响。

**响应**（200）：
```json
{ "deleted": true }
```
**错误**：404（会话或绑定不存在）

## session_skill_snapshot 注入位置

与既有 `module_snapshot` 并列，**不改 module_snapshot 的语义或结构**。

1. **`factory/control/run_execution.py:38-43`**（`_plan` 函数）

   - 写入 run JSON 的 `session_skill_snapshot` 字段

2. **`factory/control/requirement_analysis.py:302-305`**（`confirm` 函数）
   - 在 spec 确认更新 run 时一并写入
   - 同样的条件判断

## N4/N5 接线指南

### N4（GitHub 来源）
- 调用 `SessionSkillStore.create_from_data(session_id, payload, actor_id)` 即可
- `payload` 传 `origin: 'github'` + `source_ref: 'owner/repo#branch'` + `source_version: commit_sha` + `source_sha256`
- 不需要 ZIP，直接传结构化数据

### N5（前端面板）
- `GET /api/v4/sessions/{sid}/skills` → `items` 数组渲染列表
- `POST /api/v4/sessions/{sid}/skills` → `multipart/form-data` 上传 ZIP
- `DELETE /api/v4/sessions/{sid}/skills/{id}` → 解绑
- `sid` = 当前对话的 `conversation.id`
