# N11：管理员配置对话入口（接通 N2 的工具）

基线：集成分支 `7eb1749`。worktree `webuddy-next-n11`。

## 背景（主会话集成时发现的缺口，必须读懂再动手）
N2 已经做出 9 个管理员配置工具（`factory/control/admin_config_tools.py`），内部调用与表单**完全相同**的后端方法，member 调用返回结构化拒绝，密钥文本被拦截，27 条测试在案。

但 N2 把它们注册给了**所有会话**。集成时全量套件抓到 `test_real_session_mcp_server_calc_and_export_handlers` 变红，暴露出真实问题：**管理员在一个「报价助手」聊天里也会带着能改部署目标的工具**。主会话已加闸门（`7eb1749`）：只有 `actor_role=='admin'` **且** binding 显式声明 `admin_config=True` 才注册，并有 5 条闸门测试 + 变异验证（`tests/test_admin_config_surface_gate.py`）。

**结果是：配置工具现在安全了，但没有任何入口会把 `admin_config` 置为 true，所以管理员配置对话还用不了。** 你这一单就是把它接通。

## 用户结果
管理员能在一个**专门的配置对话**里用自然语言配置运行环境/自动化/部署目标，和表单改的是同一份配置。普通职能体聊天不受任何影响。

## 依据（已锁定，不要重新设计）
- 共识 §20：管理员需要**两种配置入口**——结构化表单 + 支持自然语言和配置材料输入的 Chatbox；**两种入口编辑同一份配置**，避免形成互不一致的配置来源；对话入口负责理解配置意图、补齐必要字段并解释连接检查结果。
- 共识 §20.1：模型只拿凭据引用与脱敏信息，**不需要密钥原文**；聊天和表单使用同一凭据存储及权限边界。
- README 行「配置归管理员」：管理员表单与配置对话**复用同一接口**。

## 范围
1. 提供一个**管理员专属**的配置对话入口，其会话 binding 带 `admin_config=True`。
   - `admin_config` 只能由**服务端按实际角色**决定：客户端可以请求配置面，但**服务端必须自己查 role**，不得直接信客户端传来的标志位。
   - 非 admin 请求该入口 → 403 / 结构化拒绝，且**其 binding 的 `admin_config` 必须是 false**。
2. 前端：把这个配置对话放在管理员已有的运行配置页 `/settings/runtime`（`RuntimePage.tsx`）里，与既有表单并列——这正是「两个入口、同一份配置」。**不新增顶层导航、不新增顶层路由。**
3. 对话里改完配置后，表单页读到的值必须同步（同一份真相来源）。

## 硬性约束
- **不改 `conversation_tools.py` 的闸门逻辑**，也不放宽它。你只负责让合法入口把标志位置上。
- 不改 `admin_config_tools.py` 里已验收的工具行为与密钥拦截。
- 不改普通职能体聊天（`AgentChatPage` 的 `do`/`maintain` 会话）的任何行为——**`tests/test_admin_config_surface_gate.py` 和 `tests/test_agent_chat_capability.py` 必须保持全绿，一个断言都不许改**。
- 密钥不得进入对话消息、模型提示词或日志。
- 沿用统一 AppShell 与既有米白墨绿视觉。

## 允许修改

- `frontend/src/workbench/RuntimePage.tsx`

`conversation_tools.py`、`admin_config_tools.py`、`app.py`、`App.tsx`、`Workbench.tsx`、`index.css`、`workspace/types.ts`、`runtime_routes.py`、`deploy_targets.py`、`session_skills*.py`、`Deliverables.tsx`

## 必须有测试
1. admin 走配置入口 → binding `admin_config=True`，工具清单含配置工具。
2. member 走同一入口 → 拒绝，且 binding `admin_config` 为 false、工具清单只有 calc/export。
3. **客户端谎报**：member 在请求体里自带 `admin_config: true` → 服务端仍判定 false。这条做**变异验证**。
4. 通过对话改一个配置项 → 表单读接口读到的是改后的值（同一份配置）。
5. 普通 `do` 会话不受影响（既有测试保持绿）。
