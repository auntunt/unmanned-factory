## 范围（对应报告的 M1–M4 + 一处口径修正）
1. **M1 CLI harness**：给工具加 argparse 包装，使下载后可直接 `python tool.py --input x --output y` 之类运行，不要求用户手拼 JSON 契约。保持既有 stdin/stdout JSON 契约**继续可用**（平台内调用走它），CLI 是加在外面的一层，不是替换。
2. **M4 版本标识**：工具文件内嵌版本标识，`--version` 可打印，且与平台记录的不可变版本一致。
3. **M2 工具执行包下载**：用户能下载到「可独立运行」的那一份（含 harness 与版本标识），而不只是职能体模板 ZIP。复用现有下载端点与 `X-Validation-Status` 机制，不新建一套。
4. **M3 下载核对**：下载响应给出可核对的 sha256，并提供**客户端可执行的核对方式**（随包的校验文件或端点返回的摘要），使"平台内跑的"与"下载下来的"可被证明是同一版本。不要只在测试脚本里手工比对。
5. **MFD 口径修正**：`packs/mfd-xml-conversion/pack.json:4` 的 purpose 写的是「无损转换」，与工具层 7 处诚实标注的「清单局部提取」矛盾，且这个字段会流入 agents 表并在 AgentsPage 展示。**改为与工具层一致的口径**（局部提取/清单提取），不扩口径也不缩小既有能力。只改措辞字段，不改工具行为。
