## 主会话锁定的契约（N4/N5 会依赖它，**不得擅自改动形状**；确有不可行处先回报再改）

### 存储
新增独立表（不要复用 `instruction_modules` / `skill_assets` / `project_modules`）：
`session_skills(id TEXT PK, session_id TEXT NOT NULL, data TEXT, created_at)`
`data` JSON 至少含：
`{name, origin, source_ref, source_version, source_sha256, entry, description, dependencies, import_state, dependency_state, actor_id}`
- `origin`：`"zip"`（本单实现）| `"github"`（N4 实现，本单只预留取值，不实现拉取）
- `source_version`：ZIP 走包内声明版本或空；`source_sha256` 必填（包内容摘要，来源可溯）
- `import_state`：`imported` | `rejected`
- `dependency_state`：`ready` | `missing` | `unknown`
- **执行成功不存在绑定上**，由既有 run 事件记录，不新建事件表

会话标识：`session_id` 对应现有工作会话主键（先核实是不是 `agent_conversations.id`；若实际另有其名，以实际为准并在回执写明你用的是哪个）。

### API（与既有 skill-ingestions 同族命名）
- `POST   /api/v4/sessions/{sid}/skills`      导入并绑定到该会话，返回绑定记录
- `GET    /api/v4/sessions/{sid}/skills`      列出该会话绑定
- `DELETE /api/v4/sessions/{sid}/skills/{id}` 解绑

### 编排接入
run 创建时把该会话当前绑定**快照**进 run，字段名 `session_skill_snapshot`，**与既有 `module_snapshot` 并列，不改 module_snapshot 的语义或结构**。目的：运行期间版本不变 + 事后可回查"本次加载了哪个版本"。

## 必须有测试的作用域强制（每条一个测试，缺一不可）
1. 会话 A 的绑定，在会话 B 的 GET 中**不出现**。
2. 进程/Store 重建后（模拟重启），会话 A 的 GET 仍返回原绑定。
3. 会话绑定**不**在 `instruction_modules` / agent manifest / `project_modules` 产生任何新行（直接断言这三处行数不变）。
4. 会话绑定**不**授予任何工具权限、凭据或部署权限（断言不触碰授权/目标相关表）。
5. DELETE 后 GET 不再返回该条；已产生的 run 记录与其 `session_skill_snapshot` 不变。
6. `import_state` 与 `dependency_state` 是两个独立字段，格式非法包 → `rejected`，依赖缺失 → `imported` + `missing`（即导入成功不等于依赖可用）。
