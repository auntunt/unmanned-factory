# R2：会话 Skill 访问授权（Codex P1 第二条，**越权读取**）

基线 `4d2e3f8`。worktree `webuddy-next-r2`，分支 `webuddy-next-r2`。

## Codex 的判定（事实，不要辩驳）
`session_skill_routes.py:22–28` 的 `_verify_session` **只 `SELECT 1` 确认 sid 存在**，`GET:91–94` 直接返回绑定。全局中间件对 GET 只有登录检查。
复现：管理员建会话并导入 Skill，切到**无关 member**，`GET /api/v4/sessions/{sid}/skills` 返回 **200 及完整元数据**（名称/描述/来源/依赖），预期 403/404。
上一轮那条"另一会话 URL 带错误 skill_id 删除返回 404"只证明行匹配，**不证明会话归属**——主会话当时的 V1 核查也漏了这条，验的是跨会话删除，不是跨用户读取。

## 修复范围（Codex 给定）
1. **GET / 导入 / 删除三个动作统一验证真实会话拥有者**，并尊重既有管理员规则与必要的项目授权。
2. **授权必须在取内容、外部拉取之前执行**——不能先去 GitHub 拉一趟再判权限。
3. **不把"知道 sid"当作授权。**
4. **普通用户要能导入自己的会话**（共识 §20：普通用户可从 GitHub 或完整 ZIP 导入 Skill，只作用当前会话）。但当前全局中间件默认拒绝 member 写入新路由，所以必须做**明确的窄授权接线**——
   **只放开「member 对自己拥有的会话」的这三个动作，绝不能放开所有 v4 写接口。**
