# N5：会话 Skill 前端面板 + 术语呈现对齐（D2 前端端）

基线：集成分支当前 HEAD（含 N3 契约）。worktree `webuddy-next-n5`。

## 用户结果
用户能在当前工作会话里看到、导入、移除**只属于这个会话**的 Skill，并且界面上分得清「加载一个方法」和「使用一个工具」。

## 依据（已锁定，不要重新设计）
- N3 回执 `docs/implementation/webuddy-next/receipts/N3.md` 是**权威接线契约**：三路由 `POST/GET/DELETE /api/v4/sessions/{sid}/skills`、`data` JSON 字段、session_id = `agent_conversations.id`。照它接。
- 术语对齐 §1/§2：Skill 主操作是**加载到当前会话**；独立工具主操作是**使用工具/开始对话**；两类展示字段不同（Skill 展示方法/适用范围/参考资料/来源与版本；工具展示输入输出/独立使用方式/运行条件）。
  - §2 明确：**不新增两个顶层导航**，保留现有页面编号与深链兼容，**不凭旧 pack 对象推断用途**。
- 共识 §20.2：界面对普通用户只需显示「当前会话可用」「需要管理员补齐运行条件」或具体失败原因；**导入成功、依赖可用、本次执行成功分别记录**，不能共享一个含糊的「已启用」。
- 调查报告 `survey/D2.md` 的「部分实现」四条。

## 范围
1. **会话 Skill 面板**（工作现场/会话侧）：列出本会话绑定、显示来源与版本、支持导入与移除。状态按三分显示：导入结果（imported/rejected）、依赖状态（ready/missing/unknown）、以及「本次执行是否成功」来自运行记录——**三者分别呈现，不合并成一个「已启用」**。
2. **动词对齐**：Skill 类内容的主操作文案统一为「加载」（当前完全没出现「加载」）；工具类保持「使用/调用/运行验证」。
3. **类型标签**：能力中心能看出某项是方法类还是工具类。
4. **修正错误表述**：`frontend/src/workbench/AgentManifest.tsx:25` 现在写「skill 是工具」，与产品定义**矛盾**，改为与术语对齐一致的表述。
5. 「沉淀能力」（v3 Capability）**保留现有标签与动作**，不强行归入两类之一（主会话裁决，依据术语对齐 §4「缺少类型依据的旧记录保留兼容显示」）。

## 硬性约束
- **不新增顶层导航、不新增顶层路由、不改页面编号与深链**。
- **不做全库重命名**；后端对象名（pack/agent/module/capability）一律不动，只改呈现层文案与标签。
- 不假成功：依赖 missing 就显示需要管理员补齐的具体事项，不显示「可用」。
- 沿用统一 AppShell 与既有米白墨绿视觉。
