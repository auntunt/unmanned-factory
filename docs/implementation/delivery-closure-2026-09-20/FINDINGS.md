# 现场发现与证据边界

本轮是场景验收，不用通过数量代替产品完成度。

1. **验收效率需要优化。** 开发与独立验收都反复启动浏览器；验收自行搭的代理漏处理 favicon，造成错误诊断和补修循环。一次独立验收还因剩余208秒超时而丢失最终回执。本轮保留失败，把部署审核改为清晰的 HTTP/构建合同，公网页面留到真实部署后核验；没有删除闸门或手写通过。后续应研究复用绑定提交的可信命令证据、限定验收环境责任、减少无新证据时的重复检查。
2. **预算保护是真实阻断。** 超时调用缺完整账单时按上限保守预留，导致已知成本尚未达到上限也会停止。未对账预留不等于实际费用，更不能为了继续测试清零。本轮V1仅从12增到20一次，仍失败后停止；部署验收作为独立阶段单独留账。
3. **自动接续有适用条件。** 运行中补充在可恢复 needs_human 节点自动合入；本轮使用明确记录的外部检查故障构造该节点。成功终态前尚未消费的补充仍会显示过期，不能据本次恢复场景声称任意节点实时注入或所有成功任务自动追加执行。
4. **部署脚本是管理员预注册的专用适配。** 本次 Counter 固定仓库、固定动作与指定提交由运维接线，模型不拿SSH/GitHub凭据。代表性发布通过不等于任意新项目已能自行生成安全部署模板。
5. **探针问题不能算平台问题。** 首轮公网Python探针的导入作用域错误、观察器重复批准与平台自动推进竞争、规划检出与基线不一致，均记录并修正测试接线。尤其第一次V2观察器退出导致补充未发送，不能当作自动消费失败。
6. **浏览器通路。** 内置浏览器连接超时，读取Codex原生窗口被工具限制；使用允许的Safari完成真实公网操作并截图。没有使用替代技术绕过被禁止的Codex窗口读取。

不据此扩展 MFD、PPT、独立暂停、多用户协作、知识系统、通用自动部署的能力声明。
