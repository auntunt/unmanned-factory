## 事实口径（不补假数据）
- 负责人：系统没有该字段，所有节点都显示“未记录（系统没有该字段）”。
- 当前可处理：按既有规则（发起人或管理员）写出“发起人 X 或管理员”。
- 执行器：只取运行事件里记录的 provider，没有就写“未记录”。
- 方案批准人：不推断，写“批准记录见任务现场”。
- 检查：取自 `artifacts.checks`（名称 + 退出码），没有记录就写“尚无检查记录”。
- 补丁：写明“已生成 ≠ 已验收 ≠ 已上线”；目标节点写“尚未生成，不计入交付”。
- 没有新写模型，没有迁表，没有虚构多 Agent 角色。

## 用户能回答的问题（本页范围内）
托管了哪个版本（仓库和任务的基线 SHA、分支）；谁负责（负责人未记录，这是明确暴露的缺口；执行发起人与可处理人为真实值）；在做什么，卡在哪里（任务状态 + 阻塞挂在实际阶段上）；下一步做什么（阻塞和失败节点的原因、下一步，以及去处理的链接）；交付依据（检查逐条结果 + 补丁 commit，并注明不等于已验收或已上线）。

## 未完成或边界
- 负责人和当前经办人没有数据模型，只能暴露缺口；要补需要另行设计写模型（本轮按要求不做）。
- 画布只覆盖维护子系统（维护需求和任务）；通用项目运行（ProjectPage / RunWorkspace）没有接入同一张图。
- 批准人和审批记录没有从事件里投影出来，目前指向任务现场。
- 没有做真实的网络失败（是在页面内模拟 503）；没有做超过 80 个节点的真实高密度数据，自动折叠只由单元测试覆盖。
- 画布连线没有做避让算法：同一列的兄弟节点共用一条竖线，文字不会被遮住，但没有逐条标注，含义靠图例和 hover 说明。
