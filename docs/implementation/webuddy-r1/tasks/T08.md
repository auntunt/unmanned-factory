契约④（规划者已定，变更先报）：
- 自动消费点：运行器把 run 置为 needs_human（执行暂停/失败暂停）时，若存在未消费 pending 且 run 未被取消，服务端自动以合并内容接续执行（等效 continue_run 语义，actor 记 system/auto，事件注明 auto_resume 由哪些 pending_id 触发）；不承诺执行中打断，安全节点=状态转换点。
- 正常完成（succeeded/published 等终态）：未消费 pending 标独立态「任务已结束未并入」（事件 followup.expired 或等效，含 pending_id），绝不自动开新一轮，也不标 applied。
- 取消：cancel_requested/已取消保留 pending 原状，绝不自动恢复已取消任务。
- 逐条回执：user.message 已带 pending_id；GET run 的 followups 按条含 {id, applied, ...}；前端徽标按该消息自身 pending_id 查对应条目，禁止用全局列表把部分生效标成全部已应用。
- 措辞三分：已记录（pending）/已并入后续执行（applied）/任务已结束未并入（expired）；「已并入」不得写成「已完成要求」。
- 耐久：刷新/重启后以上状态从事件重建；并发提交、校验冲突、消费中崩溃不丢失也不重复触发实际执行（沿用 collect→校验→update→mark 序）。
