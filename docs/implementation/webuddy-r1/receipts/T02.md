## B1 根因结论：代码缺陷，非单纯环境问题

T01 诊断为"探针子进程环境的凭据可见性问题"，建议配置凭据后重跑。实际根因是代码缺陷，包含两层：

### 缺陷 1（主因）：setting_sources=[] 剥离凭据源

`_run_claude()` 向 `ClaudeAgentOptions` 传递 `setting_sources=[]`，SDK 生成 `--setting-sources=`（空字符串），CLI 将其解释为"不加载任何设置源"，包括用户凭据源。即使 `ANTHROPIC_AUTH_TOKEN` 在环境中存在，CLI 也无法读取它来完成认证。

复现：
```
# 失败（空 setting-sources 剥离凭据）
claude -p 'Reply OK' --output-format json --max-turns 1 --setting-sources=
# → is_error: true, "Not logged in · Please run /login"

# 成功（user 源提供凭据）
claude -p 'Reply OK' --output-format json --max-turns 1 --setting-sources=user
# → is_error: false, result: "OK"
```

修复：`setting_sources=[]` → `setting_sources=["user"]`。user 源仅提供凭据和用户偏好设置；`strict_mcp_config=True` 已防止加载 ambient MCP 服务器。

### 缺陷 2（次因，防御性修复）：CLAUDE_CODE_* 宿主会话变量泄漏

`_worker_env()` 剥离了 `CODEX_*` 桌面宿主变量，但遗漏了 `CLAUDE_CODE_*` 宿主会话变量。当服务进程从 Claude Code 会话内启动时，SDK worker 子进程继承 `CLAUDE_CODE_MESSAGING_SOCKET`、`CLAUDE_CODE_SDK_HAS_HOST_AUTH_REFRESH` 等变量。bundled CLI 据此尝试通过父会话的消息通道刷新认证，失败后报"Not logged in"而非回退到环境凭据。

该缺陷在缺陷 1 修复后不再导致失败（`setting_sources=["user"]` 使凭据可用），但属于应清理的环境泄漏。新增 `_HOST_CLAUDE_CODE_ENV_KEYS` 集合与 `_DESKTOP_CODEX_ENV_KEYS` 对称处理。
