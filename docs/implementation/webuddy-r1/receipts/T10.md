## 调查 1：--setting-sources 各取值下的加载范围

| 设置源取值 | 认证可用？ | hooks 加载？ | permissions 加载？ | env 注入？ | MCP 加载？ | CLAUDE.md？ |
|---|---|---|---|---|---|---|
| `[]`（空） | 否（CLI 报 Not logged in） | 否 | 否 | 否 | 否 | 否 |
| `["user"]` | 是 | **是** | **是** | **是** | 是（被 strict_mcp_config 挡住） | 否 |
| `["user","project"]` | 是 | 是（两层合并） | 是（两层合并） | 是（两层合并） | 是（两层合并） | **是** |
| `None`（默认=全部） | 是 | 是（三层合并） | 是（三层合并） | 是（三层合并） | 是（三层合并） | 是 |

证据来源：
- SDK types.py 行 2243-2252：`"user"` — Global user settings (`~/.claude/settings.json`)。`"project"` — 需要它才加载 CLAUDE.md。`[]` — disable filesystem settings (SDK isolation mode)。
- SDK subprocess_cli.py 行 722-723：`--setting-sources={','.join(effective_setting_sources)}`，空列表生成 `--setting-sources=`。
- CLI help：`--setting-sources <sources>  Comma-separated list of setting sources to load (user, project, local)`。
- 本机 `~/.claude/settings.json` 结构（仅查键，无凭据值输出）：hooks（16 个事件类型）、permissions（6 条 allow）、env（9 个变量含 ANTHROPIC_AUTH_TOKEN）、enabledPlugins（8 个）。

结论：`setting_sources=["user"]` 加载的不只是凭据；它把用户 settings.json 的 hooks、permissions、env、plugins 全部带入 worker CLI 进程。

## 调查 3：隔离实验

### 实验设计

构造临时 HOME `/private/tmp/.../scratchpad/t10-canary/`，放入 `.claude/settings.json`：
- canary hook：Stop 事件写 marker 文件
- canary permission：`Bash(npm run *)`
- canary env：`T10_CANARY_ENV=canary_value_12345`

运行 `claude -p 'Reply OK' --setting-sources=user --strict-mcp-config --output-format json --max-turns 1`。

### 实验结果

CLI 报 `Not logged in · Please run /login`，退出码 0（is_error=true）。Hook marker 未创建。

原因：将 HOME 指向临时目录后，CLI 找不到绑定于真实用户主目录的认证凭据（keychain / OAuth session）。即使 `ANTHROPIC_AUTH_TOKEN` 在进程环境变量中存在，CLI 仍无法认证。这证明认证不仅依赖 env var，还依赖 `~/.claude` 下的会话状态文件或 macOS keychain 条目。

在不移动真实凭据的条件下（任务约束：绝不修改用户真实 ~/.claude，绝不输出凭据值），无法完成 CLI 认证，因此无法触发 hook 执行来观察 canary 是否生效。

**替代证据（源码级）**：SDK subprocess_cli.py 行 722-723 将 `setting_sources` 转为 `--setting-sources=user` CLI 参数。CLI 加载 `~/.claude/settings.json` 后，其中的 hooks 字段由 CLI 自身的 hook 执行器处理（与 SDK 的 Python hook 回调独立运行）。`strict_mcp_config` 在 CLI 源码中仅设置 `--strict-mcp-config` 布尔标志（行 693-694），不影响 hooks/permissions/env 的加载路径。

## 结论矩阵摘要

`setting_sources=["user"]` 是认证所必需的（`[]` 直接报 Not logged in），同时也加载了：
1. **Hooks**（未被 strict_mcp_config 挡住）——部署服务器上的用户 settings.json hooks 会在 worker 进程中执行
2. **Permissions**（未被挡住）——但 worker 的 SDK PreToolUse hook 是实际工具闸门，user permissions 不能绕过它
3. **Env**（未被挡住）——用户 env 可能覆盖 ANTHROPIC_BASE_URL 等关键变量
4. **Plugins**（MCP 部分被 strict_mcp_config 挡住，非 MCP plugins 未被挡住）

**是否改 providers.py：否。**

理由：
- 认证必须依赖 `["user"]`，无法进一步缩小
- `--safe-mode` 可关闭 hooks 但同时关闭 skills/plugins/themes/keybindings 等，副作用未经验证
- worker 的 SDK PreToolUse hook（`pre_tool_use` 函数）是真正的工具权限闸门，不受 user permissions 影响
- 正确的缓解措施是部署检查清单：确认服务器用户 `~/.claude/settings.json` 无非预期 hooks/permissions/env
