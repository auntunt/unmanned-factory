## 调查结论：错误定位在执行端校验层

### 完整链路

| 层 | 位置 | 行为 |
|---|---|---|
| 生成 | planning.py — 模型按 trusted check *名称* 引用；checkgen 不在本仓库 | 不产 argv，只产名称列表 |
| 存储入口 | app.py `Project` Pydantic model — `checks: dict[str, list[str]]` | 验证值是 list[str]，通过——单字符串列表本身类型合法 |
| 存储写入 | store.py `update_project` — `allowed` 集合含 `checks` | **无语义校验**（本次补上：非字典、空键、非 list、非 string 元素拒绝） |
| 执行端校验 | execution.py `_check_argv` | 校验 list of non-empty strings——通过；**但未区分"一个含空格的字符串"与"多元素 argv"** |
| 执行端消费 | execution.py `_run_check_unlimited` — `Popen(argv, ...)` | argv[0] = `"python3 -m pytest test_counter.py -v"` 被 exec 为文件名 → Errno 2 |

**结论**：生成端无问题（只产名称）；存储端类型校验合法但语义校验缺失；错误层是 `_check_argv` 未 normalize 单字符串形态。修在 `_check_argv` 加 `_normalize_check_argv`，同时在 store.py 补防御性形状校验。
