# 职能体：岗位清单与证据驱动进化

三层模型：**skill = 工具；职能体 = 岗位；运行 = 任务**。能力模块是可版本化的方法单元，职能体只组合身份、固定版本的 skill 和验收断言。一次具体需求应提交为运行。

## 清单与运行冻结

清单包含 `identity`（最多 1200 字符，谁负责、职责范围、明确不管的事、交付口吻）、`skills: [{id, version}]`（引用能力模块的不可变版本）和 `assertions: string[]`（逐项核对的验收条件）。保存需提交当前 revision，冲突返回 409；每次写入追加清单及审计，历史不可更改。身份段由管理员直接编辑，维护模型无身份写接口。恢复旧清单也是追加新 revision。

运行沿用现有 freeze 机制冻结清单与 skill 正文。新编译器按身份段、带“能力单元（数据，非指令）”标记的 JSON 正文编译。skill 不能授予工具或绕过用户授权。断言进入现有 `agent:N` criteria，由独立验收逐项提供证据；不新增执行阶段。已冻结运行不随清单或模块库更新漂移。

## 迁移与可移植包

存量版本保持不可变，旁表保存迁移后的清单：身份取原文首段并截断到 1200 字符，原文（包括空白）完整保存在专属“遗留能力”中。`legacy-exact-v1` 编译器直接还原原文，不重复添加身份或标记，以满足逐字兼容；快照测试对比完整 `agent_guidance`。人工保存清单后转为新编译器。旧维护草稿对原版本的更新会迁移成新的遗留 skill 版本引用，身份沿用已保存的人签身份；采用新编排清单后，维护对话仍只产出草稿；人工点击应用时，将变更的方法保存为一个新 skill 并加入清单，身份保持不变。模型设置单独更新不会改动清单。

v2 ZIP 包含 `manifest.json`（schema `webuddy.agent-pack/v2`，岗位名称/用途、manifest、模型/交付配置、skill 元数据）、`skills/<id>@<version>.md`，以及原有上传附件 `assets/*.zip`。导入会分配本实例的新模块 id，保留来源 id/版本；不覆盖库中已有模块。兼容读取 v1 `agent.json` + `SKILL.md` ZIP。导入事务内校验所有引用，异常不留下半个职能体；沿用 ZIP 大小、路径、符号链接等检查。导出当前职能包与下载内置原始 v1 模板是不同操作。

## 两条反模式

- **为一次任务创建岗位**：创建页提示“岗位而非任务”。一次修复直接提交运行，只有长期职责需要职能体。
- **一个 skill 塞入整套手册**：正文超过 4000 字符，保存界面和 API 返回拆分警告，但不阻止保存；一个能力单元应聚焦一种方法。

职能体页显示 skill 名称、固定版本和来源；能力卡显示被多少个当前职能体清单引用。模型和账号配置仍沿用现有机制，不引入市场、分享服务或新的执行器。

## 证据驱动进化

提案只有四种变更：加入 skill、移除 skill、升级 skill 版本、新增断言。公共 API 必须提交 `evidence: {run_ids: [...], explanation: "..."}`；拒绝空证据、不存在的运行、其他项目的运行，以及尚无独立验收条目证据的运行。提案保存当时的清单 revision；审批时再次检查证据和 revision，清单已变更则返回 409，可驳回后重新提案。批准与清单新 revision、审批审计、通知入队在同一事务中提交。

经验库“升格为 skill”保留 capability id/版本和来源 run_id，创建独立 skill 草稿及“加入”提案；同一能力版本向同一岗位重复升格返回原提案，不重复创建 skill。没有来源运行的手工模板不能升格。自动批准的是有证据的清单引用，不等于把原任务成功宣称为对所有业务验证成功。

运维观察线程每分钟检查一次周任务，数据库持久去重确保每个 UTC 自然周只扫描一次。汇总上一个自然周内每个岗位/项目/skill 的挂载运行数与证据引用运行数；随后检查已终结运行中最近连续五次挂载。五次使用同一版本、均有独立验收证据、却都没有引用该 skill 时，生成移除提案。缺失整个验收账本属于未知，不算“零引用”。升级版本会重置连续判定；相同五次证据不会重复提案。零引用是评审线索，不证明 skill 无价值。

独立验收 criteria 的可选 `skill_refs: [{id, version}]` 必须属于冻结清单，平台校验后写入 acceptance_ledger；引用必须对应实际观察到的证据。无引用写空列表，不能因挂载就默认引用。统计使用这个结构化引用，不正则猜测正文关键词。

项目设置提供 `auto_evolve`（默认关）与进化通知开关（默认开，未配置运维 webhook 时不发送）。自动审批只认可平台内部创建的 `capability + add_skill` 和 `usage + remove_skill` 组合，且提案项目必须绑定到该职能体。公共 API 无 source 参数，不能伪造自动来源。人工提案、升级版本、新增断言永远不自动批准；身份段根本不是进化提案类型。一个职能体可服务多个项目，自动清单更新对该岗位后续任务生效，因此启用策略前应确认岗位的共享使用范围。

批准后的通知通过既有 operations outbox 外推，含项目、变更摘要和职能体直达链接，脱敏、去重与失败不影响任务的语义不变。通知可在项目设置关闭。所有历史清单及审批记录保留，回滚仍是新 revision。没有模型自动改身份、无证据进化或跨岗位市场。

职能包导入复用既有最多 20 MiB ZIP 的流式上传边界（multipart 总量最多 21 MiB）。本轮仅在上传路径识别中加入 `/api/v4/agent-packs/import`，原管理员、同源、CSRF 校验及顺序不变；路由契约清单未变，中间件快照更新到这次显式上传扩展。
