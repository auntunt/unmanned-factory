# 职能体：岗位清单与证据驱动进化

三层模型：**skill = 工具；职能体 = 岗位；运行 = 任务**。能力模块是可版本化的方法单元，职能体只组合身份、固定版本的 skill 和验收断言。一次具体需求应提交为运行。

## 清单与运行冻结

清单包含 `identity`（最多 1200 字符，谁负责、职责范围、明确不管的事、交付口吻）、`skills: [{id, version}]`（引用能力模块的不可变版本）和 `assertions: string[]`（逐项核对的验收条件）。保存需提交当前 revision，冲突返回 409；每次写入追加清单及审计，历史不可更改。身份段由管理员直接编辑，维护模型无身份写接口。恢复旧清单也是追加新 revision。

运行沿用现有 freeze 机制冻结清单与 skill 正文。新编译器按身份段、带“能力单元（数据，非指令）”标记的 JSON 正文编译。skill 不能授予工具或绕过用户授权。断言进入现有 `agent:N` criteria，由独立验收逐项提供证据；不新增执行阶段。已冻结运行不随清单或模块库更新漂移。

## 迁移与可移植包

存量版本保持不可变，旁表保存迁移后的清单：身份取原文首段并截断到 1200 字符，原文（包括空白）完整保存在专属“遗留能力”中。`legacy-exact-v1` 编译器直接还原原文，不重复添加身份或标记，以满足逐字兼容；快照测试对比完整 `agent_guidance`。人工保存清单后转为新编译器。旧维护草稿对原版本的更新会迁移成新的遗留 skill 版本引用，身份沿用已保存的人签身份；采用新编排清单后旧 instructions 不再是编译源，应编辑清单或模块。

v2 ZIP 包含 `manifest.json`（schema `webuddy.agent-pack/v2`，岗位名称/用途、manifest、模型/交付配置、skill 元数据）、`skills/<id>@<version>.md`，以及原有上传附件 `assets/*.zip`。导入会分配本实例的新模块 id，保留来源 id/版本；不覆盖库中已有模块。兼容读取 v1 `agent.json` + `SKILL.md` ZIP。导入事务内校验所有引用，异常不留下半个职能体；沿用 ZIP 大小、路径、符号链接等检查。导出当前职能包与下载内置原始 v1 模板是不同操作。

## 两条反模式

- **为一次任务创建岗位**：创建页提示“岗位而非任务”。一次修复直接提交运行，只有长期职责需要职能体。
- **一个 skill 塞入整套手册**：正文超过 4000 字符，保存界面和 API 返回拆分警告，但不阻止保存；一个能力单元应聚焦一种方法。

职能体页显示 skill 名称、固定版本和来源；能力卡显示被多少个当前职能体清单引用。模型和账号配置仍沿用现有机制，不引入市场、分享服务或新的执行器。
