# 接续与成果入口核对 · 2026-09-10

## 发现与修复

1. 持续执行在检查成功后提交失败，恢复会重新调用开发模型。新增持久化收尾检查点（文件列表、内容签名、检查记录）；无新需求的继续会核对源码后只做收尾。源码改变时拒绝复用旧检查。已有提交且仅独立验收中断时核对提交、工作区和检查，直接恢复验收。
2. 已恢复模型会话时，首次恢复和连接重试仍会重复发送完整任务、模块与项目上下文。现在原会话只收到具体反馈/恢复原因与基础执行规则；没有会话仍发送完整上下文。新增 execution.context_delivery 记录完整与实发字符数，后续可以量化效果，不把字符数当作计费 token。
3. 页面空白继续原本被前端补成一段用户指令，妨碍后端识别“只继续”。前端改为传空文本，由后端选择恢复步骤；实际用户反馈始终交由模型处理。验收发现功能错误的自动修复明确取消只收尾标志。
4. 成果默认只看文件列表和按名称排序的图片；网页只收到 HTML，CSS 与相对图片无法加载。现在优先展示最近一次已归档的浏览器截图，提供页面/说明入口，文件列表默认折叠。静态 HTML 预览把本地 CSS 与图片从不可变 ZIP 内嵌，受大小限制，保持脚本及外网禁用。

## 验证

回归覆盖：提交失败后模型和检查均不重跑、源码变化拒绝复用、独立验收阶段不重跑开发、恢复会话只发反馈、前端空继续与新反馈区分、归档资源内嵌与路径边界、最新截图推荐。真实 Chrome 验证 CSS 呈现、脚本不执行、外部请求为零；实际成果页在桌面/390px下无运行异常与横向溢出。

## 边界

这是静态外观预览，不是部署。依赖 JavaScript 生成 DOM 的应用仍应看截图，下载后按说明运行。运行旧任务时没有新增收尾检查点的，不能倒推它曾通过哪些检查。新检查点只在本版本实际完成检查后写入。恢复优化不跳过独立验收、不更改工具授权，不把使用者新反馈当作单纯恢复。
