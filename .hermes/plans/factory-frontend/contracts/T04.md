## 契约: T04 任务详情页（九步流程时间线）

这一页是整个前端的核心 —— 用户要的「给别人看的完整流程」主要在这里体现。

### 我的输入（依赖项）
- `GET /api/task/:task_id`（T01 提供，响应形状见 `contracts/api-shape.md`）
- `frontend/` 脚手架（T02 提供：React 18 + TS + Tailwind + react-router-dom + axios）
- `frontend/src/types.ts` 里的类型定义（照 api-shape.md 写，若 T02 没建就自己建）

### 我的输出（交付物）
- `frontend/src/pages/TaskDetail.tsx`
- `frontend/src/components/PipelineStages.tsx`（九步流程条）
- `frontend/src/components/AttemptTimeline.tsx`（轮次时间线）
- `frontend/src/components/VerdictPanel.tsx`（监工判词，可折叠）
- `frontend/src/hooks/usePolling.ts`（60 秒轮询 hook，T03/T05 也会用）

### 九步流程如何呈现（关键设计）

顶部是一条横向流程条，九个阶段。每个阶段有三态：`done` / `active` / `pending`，
另加 `skipped`（当前系统还没有这个环节的数据）。

阶段与真实数据的映射（**不要编造没有的数据**）：

| # | 阶段名 | 数据来源 | 无数据时 |
|---|--------|---------|---------|
| 1 | 需求确认 | `prompt` 非空 → done | - |
| 2 | 功能拆分 | 当前无 WBS → `skipped`，提示「单任务，未拆分」 | skipped |
| 3 | 技术选型 | `harness` + `harness_version` | - |
| 4 | 系统设计 | `checks` 数组（验收判据即设计契约） | checks 为空则 skipped |
| 5 | 子代理执行 | `attempts` 非空 → done；`state==='running'` → active | - |
| 6 | 单元测试 | `verdicts` 里 `role==='regression'` 的判词 | 无则 skipped |
| 7 | 总体测试 | 当前无独立环节 → `skipped`，提示「合并到监工判收」 | skipped |
| 8 | 冒烟测试 | 当前无独立环节 → `skipped`，同上 | skipped |
| 9 | 部署 | 有 `resolution==='merged'` 的 attempt → done，显示 commit | - |

**skipped 阶段必须视觉上明确区分**（灰色 + 虚线边框 + 「暂无此环节」小字），
不许让人误以为跑过了。这是诚实性要求，不是样式偏好。

### 轮次时间线（粒度：轮次级，不要更细）

垂直时间线，每个 attempt 一张卡片，按 `attempt_no` 升序：

```
① attempt 1   [haiku]   reworked            $0.12   45s
   ├ scope       ✓ pass
   └ regression  ✗ fail   ▸ 展开看判词
② attempt 2   [sonnet]  reworked            $0.31   67s
   ...
⑨ attempt 9   [sonnet]  merged  9f8aa24d    $2.91  356s
```

要点：
- `resolution` 用颜色：merged=绿、reworked=黄、escalated=橙、blocked=红
- 模型名做成小标签（haiku/sonnet/opus 可以给不同底色）
- 花费和耗时右对齐，等宽字体
- 监工判词默认折叠，点击展开显示 `claims` 的结构化内容
  （**不是 raw JSON dump** —— check / command / expected / actual 分行显示）
- merged 那轮显示 commit 前 8 位

### 轮询要求
- 每 60 秒重新拉 `GET /api/task/:task_id`
- `state === 'running'` 时，在页面顶部显示「运行中」脉冲动画
- 轮询失败不要清空已有数据，只在角落显示「上次更新：HH:MM:SS」
- 组件卸载时 `clearInterval`（**必须清理，否则路由切换后定时器泄漏**）

### 完成标准
- [ ] 访问 `/task/T-console-empty-hint` 能看到九步流程条 + 9 轮时间线
- [ ] skipped 阶段（2/7/8）视觉上与 done 明确不同
- [ ] 点击 regression 判词能展开看到 `expected` / `actual`
- [ ] 60 秒后自动刷新（可用 devtools Network 面板验证）
- [ ] 路由切走再切回，不会出现重复定时器（React StrictMode 下也不能双跑）
- [ ] task_id 不存在时显示友好错误页，不是白屏
- [ ] `npm run build` 通过，无 TS 类型错误

### 不包含（边界说明）
- **不展示代码 diff**（用户明确不需要）
- 不实现任务列表页（T03）和统计页（T05）
- 不做任何写操作（重跑任务、取消任务等按钮一律不做）
- 不引入 UI 组件库，用 Tailwind 手写
- 不做 transcript 查看（数据库里该字段为空）

### 技术约束
- React 18 函数组件 + hooks
- TypeScript 严格模式，不许 `any`
- 样式：TailwindCSS，不引 antd/mui
- HTTP：axios
- 路由：react-router-dom v6 的 `useParams()` 取 task_id
- 时间格式化用 `Intl.DateTimeFormat`，不引 dayjs/moment
